## 目标

让同一小院在观察时，天空不只是「阴天换底图 + 全屏滤色」：

1. **时段光线**：早晨 / 正午 / 傍晚可辨（现有 TOD 滤色可保留为过渡）。
2. **云层可读**：云形、疏密、偶尔火烧云成为可反复观看的内容。
3. **成本可控**：优先叠加型水彩层，避免为每种天气导出整张 1280×720 新院子。

## 不做

- 不把云层做成每日任务、收集图鉴或签到。
- 不引入雨雪惩罚、离席损失。
- 雨雪（D）与火烧云（C）仍需单独产品确认后再制作。

## 已有资源盘点（2026-10-03，issue #51）

- `yard_sunny.png`：1920×1080 RGB，4,019,432 bytes；`yard_overcast.png`：1920×1080 RGB，3,427,343 bytes。现有两张底图已由天气代码切换，不能把改色副本当成新季节资源。
- `cloud_band_sunny.png`：1920×237 RGBA，197,101 bytes；`cloud_band_overcast.png`：1920×237 RGBA，231,984 bytes。两条已在晴阴下实际接入；运行时复制两个 Sprite 用于无缝循环，不产生第二份源资源。
- 春、夏、仲夏末、秋由 `main.gd::_update_season_tint()` 对颜色层设定：第 1–2 日春、第 3–4 日夏、第 5–6 日仲夏末、第 7 日起秋；一天为 600 秒模拟。现有时间层按晨、正午、下午、傍晚和夜晚调整色调。当前没有专属季节植被图层、冬季或火烧云资源；两张底图本身已有金黄/橙色树叶和花草，因此额外季节图层须避免重复贴花。
- 天气仍在晴/阴之间自然轮换；云带以 6.5 世界像素/秒缓移，低动效保持静止。REQ-012 的安静抬头镜头属于另一条观察设计，不和本资源需求合并。

以上尺寸/字节数是仓库源 PNG 的盘点，不是新增资源的 PCK 预算。导入压缩、PNG 重编码和 Web 导出会改变实际发布体积；每个未来资源 PR 都须报告正式 Web PCK 差值。

## 下一步提案（待制作人选择）

Codex 建议先评审一张傍晚暖色云带样张：它成本低于重画季节背景，也直接承接制作人提到的火烧云与构图观察。样张要缩至游戏实际比例，叠在晴/阴底图上看能否融进原水彩笔触，而不是成为悬浮贴纸；通过后再测低动效静帧和正式 Web PCK 增量。

若制作人更希望假期推进改变院子里的可见细节，可改为选一个季节与一处景物，先做一层局部水彩变体；现有背景上的树叶、花草已较丰富，避免用整张重画或简单换色来凑四季。雨雪仍是高成本备选，先不做。

这只是排序建议，不批准任一资源制作，也不新增天气概率、日期任务或缺席后果。每个样张 PR 需记录素材来源/授权、画布和锚点、低动效静态呈现、晴/阴底图合成效果，以及正式 Web PCK 增量。源 PNG 字节只作估算，不能代替导入和导出后的实测。本盘点由 issue #51 跟踪；表中的 C/D/E 都不是已批准的美术任务。

## 用户确认（2026-10-03）

1. **批准先做叠加型云带（B），暂缓雨雪。**
2. **云带风格须与现有院子同一水彩笔触。**
3. **接受云带缓慢平移；低动效玩家只需静止帧。**

当前实现切片：晴天一帧 `cloud_band_sunny.png` + 阴天一帧 `cloud_band_overcast.png`，由 `YardWorld` 双 Sprite 无缝缓移。
