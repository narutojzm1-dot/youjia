# REQ-20261002-010：旅人的随手拍与入册因果

日期：2026-10-02。用户实际游玩后指出：自动触发照片时画面明显放大，却看不到谁在拍、拍出的照片或照片收入相册；期待短句规范，例如“第一天，马生气了……”。具体照片文案必须与**真实捕捉到的事件**一致：本游戏存在“草泥马被大鹅惹恼”与“马晴天低头”两个不同事件，不能把马本无怒意的画面说成“马生气了”。

## 项目现状与组件所有权

| 组件 | 已有职责 | 本轮保持／最小扩展 |
| --- | --- | --- |
| `ExpressionCatalog.RULES` | 11 个拍立得事件 ID、对象、触发条件、现有标题/注释。 | 不新增收集目标、触发几率或照片格子；短句按这 11 个稳定 ID 映射。 |
| `YardWorld._apply_rule()` | 真正成立时使动物做出表情，在变化后一帧 `PhotoMoment.capture()`，保存 `photo_moments`、首遇 ID 并发 `album_updated`；此前首遇请求 1.16× 焦点 2.4 秒。 | 摄影视觉只在 **首次有真实有效抓拍** 时出现；删除无因果的摄影推镜；旧存档补抓不重放。其它场景镜头独立不动。 |
| `PhotoMoment` | 可校验、上限约束的纯场景快照，静态重建当前贴图和环境；v1 旧档没有日数。 | 新快照增加**可选、严格校验的当天数**，不重做版本、不写真实墙钟；旧档无日期继续显示原本标题，不假填“第1天”。 |
| `SaveStore` | 以已收相册 ID 为准合并/过滤快照并保存；v3 老档 ID 保持已收。 | 沿用现有保存 API 和容错行为，无 schema 迁移、无额外拍照进度。 |
| `Main._on_album_updated`、相册格子 | 判断 ID 首得、保存、现有白闪与一句“照片显影”；旧成片在手帐中小尺寸渲染。 | 存储成功之后才展示第一次成片；用同一快照画出可见拍立得，原位淡出；相册同一短句。 |
| 新 `PhotoArrival` / `PhotoDiary`（展示层） | 暂无。 | 画框/照片与文字走独立透明输入层，移动、暂停、相册可随时打断；低动效短时静帧；标题只读规则 ID+存储日+双语静态文案，不依赖网络、运行时 LLM 或系统时钟。 |

**不能用截图制造“照片”**：既有 `PhotoMoment` 是实际事件场景的有限元数据，日记展示复用它的可复现渲染，不捕捉 HUD 或随机当前背景。也不能先演“已收入相册”，再发现保存失败。字体、相框和纸底复用现有资源；相册过场不是锁镜头、任务奖励或额外可收集物。流转为：`事件规则真正成立 → 真实快照（含可选游戏日） → 现有保存 → 首得时半透明快门提示 → 同一快照成片与当天短句 → 原位轻淡出 → 可随时打开相册重读`。补抓老档若非首得，只保存真正缺失的快照，不开相机、不重演动画。

## 制作人补充：拍照反馈克制（2026-10-03）

制作人指出成片飞向相册时缩放幅度过强。现行展示保留快门闪光、真实成片和短句的显影过程；成片停留后在原处淡去，不移动到 HUD 图标、不做显著缩放，收尾不再叠加通知或按钮弹跳。照片在动画开始前已保存，玩家可立即打开手账阅读；移动、暂停和打开相册仍可打断展示但不会删除照片。低动效路径保留静止成片。

## 2026-10-02 实施观察

- 功能已从正式 `game-df8b92d` 主线分支隔离开发：`scripts/ui/photo_arrival.gd` 仅在 UI `CanvasLayer` 使用**已有** Polaroid 纸框和 `PhotoMoment` 真快照；白闪降低峰值，不新增生成美术，也不改天气与其它场景相机。`scripts/ui/photo_diary.gd` 用相同 11 个已有规则 ID 查静态中英短句。存档仍为 v4 和快照 v1；`day` 可选且限整数 `1..10000`。
- 在定向回归里发现**第3天真实抚摸马与鸭在池面排队可同一轮命中**：两个首得事件都存入旧相册，但单卡覆写会让前一张看不见。因此 `Main` 只对已成功保存的新照片维护一个**瞬时展示队列**，一张显影结束后显示下一张；主动移动、暂停、开相册或回标题会清空展示队列，**已保存相册不变**。队列不是任务、奖励或永久状态。
- 真渲染中还发现最初的 Tween 错把“展示 1.1 秒”和“飞向相册”并行，导致照片只露出约 70% 透明纸框。已换用 Godot 顺序 `tween_interval()` 和明确 `.parallel()`，定帧时 `modulate.a == 1.0` 且比例 `1.0`；竖屏 390×844 相框仍在屏内。题词将日期与短句独立成行，不留下孤单的“了。”。
- 桌面与竖屏真正拍第三天的马时，最初的摄影快照被主角腿部遮住了整张马脸。**新拍动物肖像由旅人掌镜**，不纳入前景旅人精灵和无主的绳索，真实马画作从照片中完整可见；喂草、钓鱼等旅人动作属于故事画面的照片仍保留本人。第一次完整回归还揭示“牵行时草泥马反应”必须保留旅人和接在反应后颈圈上的绳索，已对这项旧契约特判保留；未改旧照片的保存元数据或既存 v1 静态画面。
- 策划示例“第一天，马生气了”**不作为实际马事件**：目前真实马规则 `horse_pet_sunny` 最早第3天，动物反应是晴天低头；该照片写“假期第3天／马在晴天低下了头。”。真正有点恼怒的是大鹅靠近时的草泥马，才使用“草泥马被大鹅惹恼了。”。

完成边界：Godot 定向测试新日期、旧档、首得与同帧排队、低动效/打断，桌面与 390×844 真渲染，再进行 Web 浏览器、完整回归、独立最终 SHA 审核和正式 Pages 验证。PR #41 的栅栏已先合入主线；此摄影分支已快进至相同提交，不覆盖栅栏绘画/热点。
