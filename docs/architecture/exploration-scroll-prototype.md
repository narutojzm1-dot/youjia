# 画卷漫步隔离交互原型（EXP-SCROLL-PROTOTYPE，#199）

状态：**隔离研究原型，不是正式功能**。Owner：`CURSOR-CLOUD`。父单 #153。

本原型只回答一件事：已确认的「画卷漫步」形式在键鼠和触屏上怎么走、怎么停、相机怎么跟、视口变化时会不会把人丢出画面。它不接 SaveStore、Main、AudioDirector，也不引用 PR #176 的探索核心；美术全部是几何占位，停留点不代表正式地点或带回物。

## 运行

```bash
bash tools/run_exploration_scroll_prototype.sh test                  # 严格门禁跑隔离测试
bash tools/run_exploration_scroll_prototype.sh run                   # 本机窗口试玩
bash tools/run_exploration_scroll_prototype.sh export                # 导出 Web 到临时目录
bash tools/run_exploration_scroll_prototype.sh movie OUT.avi 390x844 # 按演示脚本录像
```

脚本每次新建一个临时目录（运行后保留以便查看日志，清理用 `rm -rf "${TMPDIR:-/tmp}"/youjia-scroll-prototype.*`；`PROTOTYPE_DIR` 可指定，但只接受仓库外、不是 `/`、也不包含仓库的绝对路径，且必须为空、不存在或由本脚本建过，校验全部通过后才创建或清空），把 `test/exploration_scroll_prototype/` 按原相对路径复制进去，换上 `prototype_project.godot` 与 `prototype_export_presets.cfg` 组成独立最小项目，再借用主项目已有的思源黑体子集及其许可证显示中文占位标注（字体未从资源锁恢复时退回引擎默认字体）。门禁要求检查数不少于 154，防止测试被误删后仍然通过。仓库内不放 `project.godot`，主项目不会把原型当成子项目；主项目 Web 导出继续按 `test/*` 排除。

## 候选接口（candidate，未冻结）

view-model 不知道存档、旅程或核心状态，后续 #200 回院适配器只需要它的这几项：

- `set_direction(-1 | 0 | 1)`、`step(delta)`：0 表示停下，停下后不会自行移动。
- `x`、`facing`、`is_walking()`、`walk_min()` / `walk_max()`。
- `view(viewport_size) -> {zoom, camera, visible}`：纯函数，给出相机缩放、中心与可见世界尺寸。
- `nearby_stop() -> {id, x, label} | {}`：只用于轻提示，不计进度。

场景对外只多两个入口：`release_all()`（失焦 / 切后台 / 系统取消时清空输入）与 `layout_for(size)`（按尺寸重新取景）。

## 输入规则

- 键盘：`←` / `A` 向左，`→` / `D` 向右；每个物理键各算一个来源，按住 `←` 时点按 `A` 仍继续向左；按键重复（echo）不额外入栈。按物理键位识别，AZERTY 等键盘上对应的是 Q / D 位置，提示文字暂未区分布局。
- 触屏：按住屏幕左半边向左、右半边向右；手指拖过中线即换向；被按住的半边有很淡的高亮。桌面鼠标按住按触屏处理（`emulate_touch_from_mouse`）。
- 多个来源同时按住时以最近按下的为准；松开最近的来源后回到仍按住的来源。
- 松开、触摸被系统取消（`canceled`）、窗口失焦、应用切后台都会清掉相应来源；失焦后回来必须重新按才会走，迟到的松开事件不会把方向翻回来。
- `L` 切换低动效。

## 相机与取景规则

- 先按视口高度铺满画卷高度；如果这样可见宽度超过画卷长度（超宽矮条窗口），改按长度铺满。
- 相机中心夹在画卷内，所以两端和上下都不露空白；可走区离两端各留 140 世界单位，角色在任何视口下都在画面内。
- 裁切时取景围绕地面高度，路面与角色始终可见。
- 视口变化时立即重新取景，不做缩放动画；行走从不改变缩放。
- 画卷两端用深色轴头示意尽头；走到尽头只是停住，不触发任何结束、奖励或提示。

## 体验观察与不自然处

以下来自录像与 Chrome 实测，供 #201 首片体验研究继续处理；都不是已决结论。

1. **竖屏视野很窄。** 390×844 下按高度铺满，只能看到约 330 世界单位，不到画卷的 7%；角色显得很大，远景几乎看不到。可选方向：竖屏单独设计画卷高度或取景焦点，或者允许画卷“天头 / 地脚”的纸边进入画面（属于画面内容而不是空白）。需要美术与 GAME-PRODUCER 判断。
2. **立即起停略显生硬。** 当前松开即停、没有加减速，符合“停下即停留”，但观感偏机械。若加短缓动，低动效下应保持立即起停。
3. **停留提示离景物远。** 提示固定在屏幕顶部，与停留点的视觉联系弱；正式版可能更适合在景物附近淡淡出现，或者完全不提示，让玩家自己停。
4. **半屏触控的可发现性。** 拖过中线换向好用，但没有可见按钮时首次使用者未必知道；手指会遮挡同侧画面。竖屏下操作提示折成两行。
5. **平面画卷没有视差。** 手卷本来是平面，现在的观感“像画卷”，但缺少纵深。是否加轻微视差应由美术决定，低动效下需关闭。
6. **尽头只是停住。** 这符合“不以走到终点判成功”；回院入口放在哪里、是否在两端都能回，由 #200 继续研究。
7. **Web 渲染兼容性。** 本机 Chrome 使用软件 WebGL：普通窗口、390×844 小窗、横屏小窗和 DevTools Responsive（DPR 1）都能渲染，控制台持续出现 `Could not create render target` 警告；DevTools 的 iPhone 12 Pro 预设（高 DPR）则一直黑屏。这可能只是软件渲染加高 DPR 模拟的问题，需要真机复测，交 #156 / GAME-QA 跟进。
