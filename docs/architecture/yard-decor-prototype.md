# 可逆布置对照原型（#154）

Owner：CODEX-LEAD-ASSISTANT；依据 Leader 明确拆分及认领 PR213。独立浏览器研究项目，不是 Godot 运行时接入，不读写玩家存档。几何方块身份 `fixture:decor:one`；位置、区域和数量均为实验参数，未批准正式布置规则。

运行：`bash tools/run_yard_decor_prototype.sh test` 执行 Node 模型检查；`bash tools/run_yard_decor_prototype.sh serve` 后访问 `http://127.0.0.1:8768/test/yard_decor_prototype/`。仅本机监听；正式 export_presets.cfg 既有 `test/*` 排除，无新增正式入口。

比较三个候选位置与连续自由放置。先预览，再选择确认或取消；取消移动保留旧位置，切换模式取消未确认预览，收起清除预览与放置且不消耗唯一夹具。没有数量、奖励或完成率。刷新清空只是隔离实验生命周期，不代表正式保存语义。自由区域只是院景构图采样，未标定真实地面/动线/动物遮挡；#125/#150 门禁保留。

键鼠可点选候选位置；自由模式点击预览，院景获得键盘焦点后方向键微调、Enter确认、Escape取消。所有按钮可 Tab 操作。移动尺寸用真实浏览器触屏模拟；没有动画，低动效开关不会改变状态。合成前后预览捕获点击时的当前放置，不读取或改写 PhotoMoment、历史照片；明确标注为合成材料。

复用 `assets/holiday/environment/yard_sunny.png`，未制作新画。方块是占位而非正式物件；无动物层，不能证明摆放后动物生活自然，也不能证明透视、脚底与遮挡合格。

## 本轮证据

Node 状态检查通过：取消不改旧放置、换位只保留唯一身份、切换模式取消预览、非法坐标拒绝、收起幂等和新会话清空。不是原生 Godot 测试。

实际 Chromium（本机软件环境）1280×720、390×844、844×390 操作：候选预览→确认→另一处预览→取消保留原位；切换自由模式→模拟触屏放置→确认→生成两张合成预览→收起。三尺寸均无 pageerror、无横向溢出。首次自动操作因院景未滚入视口而超时，修正测试滚动后通过；不是界面缺陷。截图见 [隔离操作记录](../playtests/2026-10-04-yard-decor/README.md)。不是真机、正式游戏心流或公网验收。

## 判断与交接

候选位置减少定位动作，但位置是否“有意义”尚需用正式物件和动物层判断；自由摆放能表达微调意图，但目前仅几何区域限制，真实地面/遮挡需要另行设计。两种模式都保留可逆选择，不自动推荐正式方案。竖屏能够同屏看院景与主要按钮，合成对照需要向下滚动；横屏需滚动看完整操作区。GAME-PRODUCER评估三个体验结果，ART-DIRECTOR审查正式透视与前景前仅将材料作比较。
