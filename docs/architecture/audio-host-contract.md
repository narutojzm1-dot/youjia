# 小院 B 方向声音宿主契约（#171）

Owner：CODEX-LEAD。基线 `a104e6b0c442aaa050453794e4538469972312f1`。依据用户已选环境＋轻音乐，以及工程督导对 [v1 的条件评阅](https://github.com/narutojzm1-dot/youjia/issues/171)。本文是接入前技术契约，不是出声、资源定稿或正式发布证明。#195 Owner 仍待认领；#194 候选听验、#196 真正游戏内听验独立。

## 生产事实与范围

现有 `AudioDirector` 创建两个 `BrowserBgmPlayer` 用于音乐交叉淡化，以及 8 个 SFX 和 2 个 UI AudioStreamPlayer。浏览器音乐共享 `browser_bgm_backend.gd` 的 `__manusBgm` 后端；不可另建 AudioContext。正式 Main 尚未调用 unlock_audio；该方法当前只设置标志，不证明浏览器已经恢复出声。TuningStore.set_values 的 persist 参数未实现持久化，不能宣称声音设置重开保持。

首片仅现有院景的环境和轻音乐；不加脚步、动物、快门、探索音景或日夜调度，不改 SaveStore。总静音和音乐独立关闭属于当前会话控制；复用现有 Master/Music 调参通路，具体玩家入口在 #195 PR 写清，不能假称已有设置界面。Ambience 独立总线供混音，不新增持久化字段或整套设置页。设置跨重开保存需另列版本化契约。

## 所有权与调用面

AudioDirector 唯一拥有播放器、cue 注册、混音和期望状态。Main 只提交院景、暂停和应用生命周期事实，不直接操作播放器。YardWorld 不逐帧推送声音状态。

候选调用面（实现可保留现有命名兼容）：

- `set_yard_active(bool)`：期望院景是否存在；幂等。false 撤销待播并停止两层。
- `unlock_audio()`：仅真实按钮或输入手势调用；尝试共享后端恢复并统一 reconcile。调用标志与实际后端状态分开，失败不能上报成功。
- `set_application_active(bool)`：后台事实，与暂停独立。
- 现有 `set_game_paused(bool)` 和 Master/Music 调参通路保持；不得令暂停、后台或解除静音相互覆写。

增加语义 cue `yard.ambience` / `yard.music`；音乐使用既有音乐双播放器，环境使用一个独立 BrowserBgmPlayer、同一共享后端。不能连续调用 play_music 播两层导致互相替换。缺失任一轨只让该层静音，不阻断入院或另一层。模板 cue 保持兼容，但不是本片新行为授权。

## 状态合成与生命周期

保留独立事实：yard_active、application_active、game_paused、各层会话音量/启用、gesture_attempted；后端实际运行/等待手势是观察结果，不以布尔解锁替代。reconcile 只根据最终事实发出必要变化，不能把历史事件排队补播。

| 条件 | 必须行为 |
| --- | --- |
| 标题或无院景 | 两层停止、清空播放器 stream；失效旧异步任务，不播标题音乐 |
| 入院但未获浏览器许可 | 保留最终期望，不循环创建播放器，不假报出声 |
| 院内、前台、可播放 | 环境与音乐并存，各自音量有效；重复入院通知不重启曲目 |
| 游戏暂停、仍前台 | 沿用现音乐 -8 dB duck；环境首片采用相同临时 duck，参数可听验调整，不重启、不把暂停当离院 |
| 应用进入后台 | 两层显式暂停，保留播放位置及期望；树暂停不能替代此动作 |
| 回前台 | 尝试恢复原位置；浏览器拒绝则等待下一真实手势，不循环补播，不自行重复建声源 |
| 会话总静音 / 音乐关闭 | 静音仍完整可玩；音乐控制不影响环境；后台优先于任何恢复播放请求 |
| 离院 / 重建院景 | 递增生命周期代号，取消 tween/旧回调；停止并清 stream，再按引用释放缓存 |

Main 是唯一应用事实适配者：实现采用 Main/root `_notification` 的 `NOTIFICATION_APPLICATION_PAUSED` / `RESUMED`；Web 隐藏标签页若目标浏览器不可靠映射这些通知，则在同一 Main 适配者改用一个 visibilitychange 桥，并禁用该平台重复通知路径。不得同时让 backend 和 Main 各自决定应用活跃；backend 只执行音频状态。实现前在实际导出记录隐藏/恢复事件，未可靠验证不能把后台验收记通过。

标题进入按钮 `_start_holiday` 的真实 pressed 调用栈中，在世界建立完成并确认院景后设 yard_active，再尝试 unlock/reconcile；不得 defer 解锁。键盘确认和已有触屏转发同样测。程序化重建不能伪装新手势。初次手势前的多次状态变化仅保留最终值；返回前台等待手势时由 Main 真实输入入口重试，不消费或改变原游戏输入含义。

两个播放器及后端控制节点是 ALWAYS，必须明确执行后台暂停。清理仅撤销场景资源，不断开 Autoload 级 TuningStore.value_changed 连接。异步恢复/解码完成须检查生命周期代号、当前 cue/stream 身份及最新期望，旧完成不得使已退出的院景重新出声。

## 资源与失败约束

#194 文件仍是候选。音乐/环境缓存键对应实际 PCM，不得两个不同轨共用一个 key；记录压缩体积、采样率、通道、时长和解码峰值（两轨加交叉淡化同时驻留），不只报告文件大小。缺失、损坏、超预算或 Web 后端失败分别验证安全降级；不能为了降级另启第二套音频引擎。

离院清 stream 后按共享引用释放缓存；重新入院可再准备，不能每次入院累计 player/backend/cache。保留授权来源、循环接缝和实际试听记录；逻辑 runner 不证明无爆音、无接缝或听感舒适。

## #195 可认领交付与验收

认领先回报 Agent-ID、分支、文件范围并登记需求表。允许修改 AudioDirector、现有 BrowserBgmPlayer/backend 的必要兼容点、Main 的事实适配和最小会话控制；不改探索、动物行为或存档，不接管其他 Owner。资源未审可使用隔离夹具验证状态和生命周期，不能将夹具或未审候选发布到正式游戏。

1. 状态测试覆盖解锁前进入/离开、连续进出、暂停与后台交错、静音恢复、丢失/迟到回调、缺失单轨和重复通知。测试实际生产协调入口，不能只写镜像 helper。
2. 严格回归与 Web 导出；记录正式标题首次真实鼠标/键盘/触屏进入到出声的证据，以及浏览器拒绝恢复后下一手势重试。
3. 桌面与移动浏览器验证双层并存、音乐独立关闭、总静音、后台恢复；模拟触屏不能冒充真机。每平台版本和未覆盖项分列。
4. 连续 10 分钟并多次进出，记录声源/backend/cache 数量与内存是否增长、循环接缝、音量舒适度；耳机/扬声器结果交 #196。首片不靠自动化布尔返回声称听验完成。
5. 最终 SHA 独立子代理审查、必要体验通过后才可合入；发布另核对 Actions、manifest、实际 PCK。用户只需对完整候选的音乐比重/舒适度提出判断，不承担逐接口技术审批。
