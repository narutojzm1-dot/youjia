## 提案结论

首个验证切片先复用鹅与草泥马现有的安静姿态，呈现平静共处；不为“友好”再画一组重复的站姿。鹅与马的轻冲突可以复用鹅现有张翅警觉画，但目前的马只有一张低头站姿，画面里看不出它在回应鹅。若产品确认这组关系演出，建议只补 **1 张马侧身让步姿态**，由短暂换帧配合角色根节点退开一步，再回到既有站姿。

这是一份小切片提案，不批准批量动画、攻击画面或通用关系演出图库。任何新资源须在产品确认演出因果后再制作。

## 建议的最小资源

### 马侧身让步（1 张完整画作）

- **用途：** 作为鹅与马短暂对峙后，马主动让开空间的可见回应；鹅继续使用现有警觉画。
- **画面意图：** 同一匹栗色马微抬头、耳朵侧转，一只前蹄轻轻抬起或落到侧后方，身体重心清楚地留在支撑蹄上。读感是“不想争、退开一步”，不是受惊逃窜、攻击、受伤或痛苦。
- **规格：** 一张完整的 1254×1254 RGBA 透明 PNG，保持马当前左向原生朝向、鬃尾和单蹄造型。完整剪影留在画布内，不带纸底、地面贴片或硬编码阴影。
- **锚点：** 以支撑蹄所在的实际地面线测量 `ground_anchor`，并在 `manifest.json` 记录 `alpha_bbox`、透明度检查和 `native_facing=-1`。与现有马在约 110 世界像素可见高度下对齐；交互开始/结束时不能跳脚或改大小。由于支撑姿态改变，不要求锚点沿用相同像素坐标，但运行时根位置须保持稳定。
- **表现接入：** 作为单次回应帧，不循环播放。可在短暂 encounter 阶段换到此纹理，同时让马的根节点后退一个短步，再还原 `idle`。根移动由行为层负责；不得压扁、拉伸或旋转现有马图伪造退让。
- **数量与成本：** 首切片只增加 1 张全角色画作，不先做整套 8 帧循环。源 PNG 目标不高于现有 `horse.png` 的 1,508,497 字节；合入资源 PR 时实测 Web PCK 的净增量并记录，不按 PNG 文件大小冒充 PCK 增量。

### 鹅与草泥马的平静共处（先不新增画作）

先以 `goose_calm.png` + `llama_idle.png` 组合验证：两个角色在合理距离内自然停留、各自可随时离开；用行为发生率/共同停留作为关系差异，不加爱心、关系数值或强制贴近。鹅的 `rest` 可用于普通休息，不额外声称它是专属关系姿态。若真实画面测试显示玩家无法分辨“同场”与“关系回响”，再基于已批准演出的具体接触动作另开资源切片。

## 来源与集成要求

新画作以仓库已批准的 [`horse.png`](../../assets/holiday/characters/cast_v2/horse.png) 为唯一角色身份与笔触参考；沿用项目内原画制作流程，不引入来源不明的外部照片或角色设计。资源 PR 应同时提交：

1. 可复核的原画母版、制作提示/流程记录和 SHA-256；原始素材保留在 `art/concepts/`，不可只提交被裁剪的运行图。
2. 与 `manifest.json` 一致的画布、真实透明边界、朝向、锚点和 alpha 审计；现有 `horse.png` 不覆盖。
3. 在游戏目标尺寸下与原马并排检查颜色、轮廓、透视和笔触，并验证交互换姿无落脚跳变。
4. Godot 导入及 Web 导出后记录 PCK 净增量；若资源体积明显超过单张同尺寸马画，先检查透明边缘/导出压缩再决定是否调整画布或细节。

## 与关系逻辑的边界

资源表现“发生了什么”，不决定为什么发生。鹅对马的紧张倾向、鹅与草泥马的平和倾向及玩家互动留下的长期记忆仍由 [`animal-relationship-model.md`](animal-relationship-model.md) 定义；关系记忆不直接切换纹理。短暂 `encounter` 只发出有界动作标记，现有相册规则可旁观拍摄，不复用作行为引擎。

本提案没有确认关系数值、发生概率、具体触发原因或最终文本。首个演出经产品确认后再交美术切片；此前不生成新资产、不改变策划基准。
