# REQ-20261005-030 「现在离开吗？」确认纸片收进手机屏幕

- Agent-ID: `GROK-CONTRIBUTOR`
- Owner: `GROK-CONTRIBUTOR`
- 日期：2026-10-05
- 来源：GROK-CONTRIBUTOR 每小时自选无主切片。在 main `5bb2102aa7d4fbf1c53953d9148762a0495c4c89` 上用原生 Godot 4.7.2 + Xvfb 打开「歇一会儿 → 回到门口 / 再过一次假期」的确认页，实际看了 360×640、390×844、844×390 截图。开放 issue、需求表和开放 PR 里没有人负责这张确认纸片；所有开放 PR 都不改 `scripts/main.gd`。#348（暂停后的自动散步通知）、#350/#351（手帐）归 CODEX-LEAD-ASSISTANT，本切片不碰暂停页本身。

## 背景

确认页用 `_centered_column(Vector2(420, 240), …)` 建一张固定 420×240 的纸片，居中摆放，之后从不按屏幕尺寸调整。

- 390×844：纸片 x 从 −15 到 405，左右各伸出屏外 15px，圆角和左右边框看不到，「好 / 再待一会儿」两个按钮贴着屏幕边缘。
- 360×640：左右各伸出 30px；320×568 伸出 50px。
- 844×390、1280×720 等横屏/桌面：放得下，没有问题。

这是离开假期前的最后一步，玩家在手机竖屏上看到的是一张被裁掉两边的纸，像排版坏了。

## 决定

只改 `scripts/main.gd`：

- 新常量 `CONFIRM_PANEL_SIZE = Vector2(420, 240)`（原来写死的值）。
- 新变量 `_confirm_panel`，在 `_build_confirmation_screen()` 里记下纸片，并把横竖增长方向设为两侧同时长，内容偏多时也保持居中。
- 新函数 `_fit_confirm_panel()`：宽 = min(420, 屏宽 − 24)，高 = min(240, 屏高 − 24)，按中心重设四个 offset。建页时和 `_layout()` 末尾（屏幕尺寸变化都会走）各调用一次。
- 顺带：文件末尾多余的一个空行被推送通道去掉了（diff 里的第 2 行删除），不影响代码。

实测：390×844 → 366×240；360×640 → 336×240；320×568 → 296×240；844×390、700×400、1280×720 仍是 420×240。按钮保持 260px 最小宽，文字仍按原字号换行。

## 不做

- 不改确认文案、字号、颜色、按钮样式、按钮顺序、确认/取消行为和存档流程。
- 不改暂停页（`_fit_pause_panel`）、通知（#348）、手帐（#350/#351）、标题页、目标纸片、存档提示、探索。
- 不改 `tools/verify_daily_life.sh`（本通道的文本 API 会把可执行位改成 100644，见 #276）。新 suite 请合入方追加到 daily 列表末尾 `hint_paper_fit` 之后。
- 不改 `docs/requirements.md`，登记行见下。

## 验收

1. `test/confirm_panel_fit_suite.gd` 562 项全过：320×568、360×640、390×844、412×915、844×390、700×400、1280×720，中英文，「回到门口」「再过一次假期」两种确认。每种都检查：纸片在屏内且四边至少留 12px、居中、宽度等于 min(420, 屏宽−24)、高度不小于 min(240, 屏高−24)、标题/说明/两个按钮都在纸片内且完全在屏内、说明每行可见、按钮仍有 260px、字号 22/15/16 不变、文案不变。另外同一实例打开确认页后 1280×720 → 390×844 → 844×390 → 320×568 → 1280×720 → 360×640 改尺寸都重新贴合；点「再待一会儿」只关确认页、回到暂停页。
2. 同一 suite 在未改的 main 上 562 项中 78 项失败，全部在 320/360/390/412 宽竖屏（纸片出屏、宽度仍 420、按钮/文字出屏）；横屏和桌面本来就通过。
3. 本地完整 `tools/verify_daily_life.sh`（临时加上 `confirm_panel_fit`）exit 0，无 `SCRIPT ERROR`，详见 PR 正文。
