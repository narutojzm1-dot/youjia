## 背景

拍到新照片时，`PhotoArrival` 在屏幕正中放一张 240×300 的拍立得，「咔嚓」说明文字固定在相纸上方 46px（34px 高 + 12px 间隙）。整组需要约 346px 高。屏高不到 408px（相纸居中时，上方要留 46px 放说明，再加 8px 边距）时，说明文字就贴顶或出屏；相纸本身只在 640×300 贴满上下边：

| 视口 | 「咔嚓」说明 y（34px 高） | 相纸 y 范围 |
| --- | --- | --- |
| 844×390 | −1（顶边裁掉） | 45–345 |
| 700×400 | 4（贴顶） | 50–350 |
| 667×375 | −8.5（顶边裁掉） | 37.5–337.5 |
| 844×340 | −26（大半出屏） | 20–320 |
| 568×320 | −36（整行出屏） | 10–310 |
| 640×300 | −46（整行出屏） | 0–300，上下贴边 |

竖屏（320×568 / 360×640 / 390×844 / 412×915）和 1280×720、1024×600 本来就完整。另外相纸只在 `play()` 时定位一次，显示期间转屏或改窗口大小不会重新居中（1280×720 开始后缩到 390×844，相纸停在 x=520，右边出屏）。

## 决定

只改 `scripts/ui/photo_arrival.gd`：

- 新常量 `SHUTTER_GAP = 46`、`SHUTTER_HEIGHT = 34`、`VIEW_MARGIN = 8`、`MIN_FIT_SCALE = 0.5`。
- 新静态函数 `fit_layout(viewport)`：整组（说明 + 相纸）放得下且四周留 8px 时，**完全沿用原来的居中满尺寸位置**；放不下时，相纸绕中心等比缩小（不低于 0.5，也不放大），说明和相纸作为一组在屏幕上垂直居中。
- 新函数 `_layout()`，`play()` 改为调用它；监听视口 `size_changed`，相纸显示中改尺寸会重新排版。
- 照片内容、文案、淡入淡出时长、低动效路径、鼠标/触摸穿透都不变。

实测（改后）：568×320 相纸缩到 0.86（258px 高），640×300 缩到 0.79（238px 高），844×390 保持 1.0 但整组下移到 y=22 起；竖屏和桌面像素不变。

## 不做

- 新 suite 请合入方追加到 daily 列表末尾；本通道不改 shell（可执行位见 #276）。
- 不冒真实手机、浏览器 DPR 或触摸验收；只做原生 headless 几何。

## 验收

1. `test/photo_arrival_fit_suite.gd` **418 项全过**：12 个视口 × 低动效/标准两条路径，加显示中 1280×720 → 568×320 → 640×300 → 390×844 → 1280×720 改尺寸。检查相纸和说明都在屏内 ≥8px、说明在相纸上方不压照片、水平居中、等比、缩放 0.5–1、缩小后仍 ≥200px 高、两段文字非空、不挡输入；竖屏与桌面位置/说明位置与原公式一致。
2. 未改脚本时同一 suite **25 项失败**（6 个短横屏出屏 + 改尺寸不跟随）。
