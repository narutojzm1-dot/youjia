# REQ-20261005-031 短横屏标题页整列留在屏内

- Agent-ID: `GROK-CONTRIBUTOR`
- Owner: `GROK-CONTRIBUTOR`
- 日期：2026-10-05
- 来源：GROK-CONTRIBUTOR 每小时自选的无主切片。在 main `efda46416da095e8cb83eb76f1d9a5e7aa800dd9` 上用原生 Godot 4.7.2 实测了标题页在 568×320、640×300、844×340、640/740/800×360 下每个控件的位置。标题纸片是本通道之前做的 REQ-20261005-028，开放 issue、需求表和开放 PR 里都没有人负责标题页排版。开放 PR 都不改 `scripts/main.gd`（只有 #375/#176 改 `scripts/exploration/`，其余改 `art/`）。#382（确认页取消后音量）和 #150（存档）都不碰。

## 背景

标题列 `_layout()` 只分两档：屏高 ≥500 用原尺寸，<500 用"短横屏"字号（标题 28、简介 14、操作说明 12、行距 8），上下各留 20px。按这一档排，整列内容高 321px：标题 42 + 副标题 27 + 简介两行 47 + 两个主按钮各 44 + 开源声明 30 + 操作说明两行 39 + 6 个 8px 行距。

- 568×320（iPhone SE 一代横屏）：列只有 280px 高，内容从 y=20 排到 341，操作说明（y 302–341）有一半在屏幕下面，也掉出了纸片（纸片被夹在 y 6–316）。内容也不再居中，整体往下偏。
- 手机横屏浏览器：360/390 高的手机横过来，地址栏和底栏再占 40–60px，可用高度只有 300–340。640×300、844×340 的情况和上面一样，操作说明掉出屏外和纸片。
- 640/740/800×360：刚好卡在边上（内容 321 > 列 320，溢出 1px），还没有看得见的问题。

标题页是玩家打开游戏看到的第一屏，手机横屏时操作说明（"点草地走过去……"）被切掉，看起来像排版坏了。

## 决定

只改 `scripts/main.gd`：

- 新常量 `TITLE_TIGHT_MAX_HEIGHT = 360`。
- 原来 `_layout()` 里写标题列的那 9 行搬到新函数 `_fit_title_column()`，`_layout()` 改为调用它（屏幕尺寸变化都会走）。
- 屏高 ≥500 和 361–499 两档的数值与原来**完全一样**。
- 新增"紧"档（屏高 ≤360）：上下边距 20→8，行距 8→4，标题字号 28→24，副标题 18→15，"走进院子 / 翻开相册"按钮文字 16→14、最小高度 44→40（最小宽 260 不变），"开源软件声明"14→12。简介和操作说明字号不变（14/12）。
- 每次调用都把三档的数值全部重新写一遍，所以从短屏转回大屏时会恢复原值。

实测（中英文一致）：内容高 321→278。568×320 整列在 y 21–299，纸片 y 7–313；640×300 在 y 11–289；568×300 也放得下。两个主按钮 480×42，仍可点。

## 不做

- 不改标题页文案、颜色、纸片样式（REQ-028）、按钮顺序和行为、相册/开源声明入口。
- 不改 ≥361 高的任何布局：667×375、844×390、700×400、1280×720、390×844、360×640、320×568 的字号/行距/按钮高与 main 完全相同（suite 逐项断言）。
- 屏高 <300 不在这次范围内（内容 278 + 边距 16 = 294 是下限）。
- 不改暂停页、确认页、目标纸片、存档提示、手帐、探索。
- 不改 `tools/verify_daily_life.sh`（本通道的文本 API 会把可执行位改成 100644，见 #276）。新 suite 请合入方追加到 daily 列表末尾 `confirm_panel_fit` 之后。
- 不改 `docs/requirements.md`，登记行见下。

## 验收

1. `test/title_short_landscape_suite.gd` 1541 项全过。紧档：568×320、568×300、640×360、640×300、740×360、844×340、800×360。常规档：667×375、844×390、700×400、1280×720、390×844、360×640、320×568。中英文都测。每种都检查：7 个控件都可见、完全在屏内且离边 ≥4px、都在纸片内、没有被压扁；整列垂直居中；简介和操作说明每行可见；两个主按钮至少 260×40（常规档 260×44）；行距和 7 项字号/按钮高等于该档的期望值；文案不变。另外同一实例 1280×720 → 568×320 → 844×390 → 640×300 → 390×844 → 844×340 → 1280×720 改尺寸都重新排版、能恢复；568×320 下真实鼠标点击"走进院子"能进院子，回到标题页后仍然完整。
2. 同一 suite 在未改的 main 上 1541 项中 144 项失败。568×320、568×300、640×300、844×340 是几何失败（操作说明出屏、出纸片、列不居中）加档位数值；640/740/800×360 只有档位数值不同（几何本来就刚好放下）。常规档 7 个尺寸在 main 上全部通过，说明没有改动这些尺寸。
3. 本地完整 `tools/verify_daily_life.sh`（临时把 `title_short_landscape` 加到列表末尾）exit 0，日志里没有 `SCRIPT ERROR` 或 FAIL；其中 title_card 251、hint_paper_fit 4653、confirm_panel_fit 562、title_short_landscape 1541 项都通过。
4. 真实手机浏览器（DPR 2/3、带地址栏的横屏）复核需要合入方或 QA 在导出包上做。本通道只有原生 Godot。
