## 问题（main `267b0cb` 原生 4.7.2 渲染，见体验记录 before/）

存档写不进去时弹出的「保存暂时无法继续」纸片是固定 352px 宽、顶边 y=90、水平居中：

- 360×640 / 390×844 竖屏压住右上「假期第 1 天」；360 宽时右边出屏 2px；360 英文目标纸片折成三行（底边 y=100），纸片还压住目标纸片。
- 568×320 短横屏压住天数标签；640×300 还往下压住「翻开手帐 / 天气」按钮排 33px。
- 消息左对齐、按钮居中，看起来是歪的。
- 按钮写死中文「再确认一次」，英语界面也是中文；消息在建界面时取一次，切语言后不刷新。

## 决定

只改 `scripts/main.gd` 里这张纸片自己的展示：

- `_build_save_status()`：消息与按钮放进 `BoxContainer`（字段 `_save_status_box`、`_save_status_message`），消息居中，按钮走新键 `save.retry`（中「再确认一次」/英「Try again」）。
- 新 `_fit_save_status()`：宽度 ≤ 屏宽 − 20（最多 352）；顶边仍从 90 起，若与可见的目标纸片 `_hint_panel` 或天数标签 `_day_label` 横向重叠，就落到它们下沿 + 8px。高 ≤ 360 的横屏改成「文字在左、按钮在右」一行（最宽 548，按钮 168×44，纸面上下留白 4px、字 15px），免得压到底部按钮排。
- 调用点：`_layout()` 天数标签就位后一行；`_refresh_hud()` 在纸片可见时随目标纸片重贴；`_show_save_pending()` 显示前贴一次；`_refresh_texts()` 刷新消息和按钮文字并重贴。
- `localization/zh-CN.json`、`en.json` 各加 `save.retry` 一行（插在 `notice.save.pending` 前，不动它那一行）。

## 不做

- 不改 `_input`、触摸归属、确认层（#470 / #382 Assistant），不碰 `_retry_save`、`_on_save_*`、`_save_problems` 等状态、协议和成功条件；纸片何时出现、何时收起、按钮何时禁用都不变。不靠排版藏起保存问题，也不解锁未确认离开。
- 不碰键盘焦点（#459）、照片/天气（Producer）、tooltip（#473/#480）。
- 英语 360 宽目标纸片折三行是另一个切片，这里不混入。
- 同屏底部普通通知（如「风很轻。你把行李放在门口。」）切英文后仍是中文，也不在本切片。
- 只做原生 headless / Xvfb opengl3 验证，不冒真实浏览器、DPR、真机验收；受控保存问题只在测试进程内构造，不冒真实磁盘故障。
