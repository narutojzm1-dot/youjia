## 问题

左上角目标纸片（`_hint_panel`）的高度在 REQ-20261005-029 后已跟着行数伸缩，但宽度始终撑到最大可用宽度（最多 520px 文字 + 18px 纸边）。目标文字通常很短，于是（原生 4.7.2 测量，见[体验记录](../playtests/2026-10-06-REQ-045-goal-paper-hug/README.md)）：

- 844×390、915×412、1024×600、1280×720：首个目标「目标：窗台花箱 · 看看花箱（空格/按钮）」只有 273px，纸片 538px，文字右边约 **256px 空纸**压在远山/屋顶上。
- 700×400：右边空 188px。
- 640×360 / 568×320 短横屏：紧凑文案自带换行，两行最长 138px，纸片却 478 / 406px，右边空 **331 / 259px**。
- 390×844 / 360×640 竖屏：右边空 81 / 51px。

## 决定

纸片左缘、高度规则、字号、文案、最大宽度都不变，只让宽度贴合文字：

1. 按文案自带的换行把目标文字分段，量出最长一段的实际宽度。
2. 每一段都能在原最大宽度内放下时，文字框宽 = 最长一段 + 2px（最窄 120px），纸片仍是文字框 + 18px，所以文字右边和左边一样约 9–11px 纸边。
3. 有任何一段放不下、需要自动换行（例如 360 宽英文长目标），仍用原来的最大宽度，换行结果与现在完全一样。贴合后若行数和最大宽度下不同，也退回最大宽度。
4. 只在文字、可用宽度、字号或可见性变化时重新测量；`_refresh_hud` 每帧调用时直接复用上次宽度，不每帧重新排版。

目标随走近的东西变化时纸片宽度会跟着变（左缘固定），像一张贴在角上的小签；没有加动画。
