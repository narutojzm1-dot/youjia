## 玩家承诺与循环

玩家做出一次可选的照料行为，应立刻看出“是我给了这只动物鱼，它有反应”。效果与对象绑定，不是全屏成就、不要求继续操作，不暗示需要刷分。内容仍服务于“注意动物—轻轻互动—动物回应—记住这个瞬间”的无压力循环；不改变鱼种、钓鱼概率、照片条件、日程或存档格式。

## 本次可独立验收的第一切片

**成功投鱼给鸭或鹅后**，具体被喂的那只鸟周围出现短时暖色爱心（程序性绘制，约 1.8 秒）。提示应跟随鸟的位置，不因另一只鸟靠近而错位；目标区附近可见，且不拦截点击。启用 `ui.reduced_motion` 时爱心不漂浮，仍短时静态可见。没有鱼、鱼在路上过期、距离不够或点错目标时不出现成功爱心，不改变旧有鱼消耗与通知。

首切片只动世界交互成功分支和对象反馈覆盖层；不改 `sequence_resident.gd`、角色行走倍率、玩家投喂动作帧或 REQ-001 负责人已做的步态 PR #27。现有鸟贴图只有 `idle`，暂不伪称有啄食帧或表情；后续若增加实际动作资产，必须另做对齐与足部锚点检查。

## 第二切片：抚摸与浇水（2026-10-02）

用户随后明确本作“每一帧都是精致的绘画效果”。因此抚摸牛/羊/马后，针对**真正被摸到**的动物绘制一簇短时的透明手绘水彩心意，随它移动；花圃仅在种子或嫩芽当日首次成功浇水时，于原土壤画作上方绘制短时透明水彩水滴。两者不是替换角色或植物的粗糙几何图标，也不把反馈计时保存进相册。启用低动效时仍显示短时静止画，不向上漂浮；未达到抚摸距离、重复浇水或未产生进展时不庆祝。后续若需让动物有点头/亲昵动作或让苗叶抖落水珠，应新增同风格绘画帧和检验，不以局部拉伸现有角色画作冒充。

## 剩余工作与退出条件

此需求**不会因投鱼、抚摸与浇水切片合入即标记完成**。其余捡草、喂/牵羊驼、钓鱼、种花/收获及更细的投鱼动作仍需逐项盘点：每项的成功路径应有相称的对象动作、场景变化或近身提示，而不只靠长段 HUD 通知；没有发生的动作不能冒出成功效果，避免连按重复刷屏。角色动作归 REQ-001 负责人，动物回应及世界特效需事先协调接口和文件范围。必要时拆成独立 PR，完成实际 Web 游玩与最新构建复核后才关闭 [issue #30](https://github.com/narutojzm1-dot/youjia/issues/30)。
