### 2026-10-02 · REQ-003 产品定位确认与 REQ-011 世界回响

- **用户决定：** 游戏定位为“轻陪伴为主，轻放置为辅”。玩家在小院里的行动有意义；动物或地点可以在之后的行为和小故事中回应这段关系。
- **设计边界：** 休闲不等于取消随机性。钓鱼空钩、偶遇未发生或错过单次咬钩是世界的一部分，不是玩家绩效失败；不能导致长期进度损失或逼迫玩家重复劳动。探索和彩蛋应从世界自然发生，不列成必须完成的任务。
- **后续要求：** 以 [REQ-20261002-011](requirements.md) 拆解少量可感知、可验证的后续回响，先做有边界的垂直切片，再决定保存状态与内容扩展方式。
- **关系模型假设：** 制作人提出用轻量羁绊/关系系统派生动物行为，例如大鹅可能与马冲突、与草泥马相处融洽；玩家互动也可能改变之后的关系和故事。此为待验证方向，不预设复杂引擎、固定脚本或数值好感度条，详见 [issue #45](https://github.com/narutojzm1-dot/youjia/issues/45)。

### 2026-10-02 · DOC-007 制作人旅行灵感成为游戏底蕴

- 制作人在同一旅行地点住了许多天，面对相似的天空、树木和水面，却因晨/午/晚光线、每天不同的云、火烧云和构图变化而不厌倦；把汽水瓶放入海滩前景，也能拍出不同照片。
- 静静坐着、暂时离开工作生活带来放松；持续观察与不经意发生的趣味让熟悉地点值得反复回去。
- **设计含义：** 先做深一处小院，让天空和时段成为内容，摄影探索玩家的构图表达，偶遇保持自然而非打卡。具体美术/交互方案见 [REQ-20261002-012](requirements.md)。
- 制作人补充的镜头方向：主人安静坐在院子时，动物小冲突可能从远处经过；镜头可以先交代远景，再转入主人第一视角，跟随并聚焦近景，最后形成照片。此为轻量、可打断的场内摄影演出探索，不要求每次互动触发过场或制作长 CG。

## 架构

### 2026-10-02 · 统一行动选择与可记录的院子道具

**决策：** 空格键与 HUD 行动按钮共用同一个动作选择结果，按钮文案、目标和触发距离一并计算。指针选择保留具体动物；走近期间目标移动时继续跟随，新的无效点击会取消旧路线。牵行时的主动作固定为放开。

花圃与钓鱼点作为独立场景节点绘制，并把有范围限制的状态写入事件照片。旧存档已获得开花或钓鱼记录、但照片缺少相应道具的玩家，在下一次真实开花或收杆时补拍；保留原有收集记录，不重复奖励。

**验证：** Godot 4.7.2 自然行动、照片序列化与竖屏视口检查；路线遇上动物挡住落脚点时，在安全距离内结束散步。

**当前状态：** 已完成，PR #14 已合并并发布。

### 2026-10-01 · 水彩背景贴图架构 vs. 真实场景化院子

**决策：** 当前院子使用单张水彩背景图（`yard_sunny.png` / `yard_overcast.png`）作为底层，所有动物、植物、互动元素以 Canvas 图层叠加绘制。
**原因：** 初期最快路径；水彩美术已定稿，短期内无法替换。
**残留风险：** 叠加图形无法与背景进行真实 3D 遮挡；植物床、钓鱼点、草堆等交互点位必须人工与画面纹理对齐，任何偏移都显假。动物无法真正"走进"背景细节（如穿越围栏、藏在草丛）。
**后续建议：** 后续 PR 中将院子重构为真实 2D 场景（独立草地/围栏/水塘等 Sprite 节点 + 碰撞多边形），实现真正的图层遮挡和可走地面。用户已明确表示对此开放。
**当前状态：** 维持现状；正在规避策略（用椭圆替代矩形、用椭圆轮廓替代圆弧指示，减少"贴纸感"）。

## 美术 / 互动体验

### 2026-10-01 · 植物床：禁止使用矩形叠加

**决策：** 植物床不得使用实心矩形（`draw_rect`）作为土壤视觉。
**原因：** 直角矩形与水彩背景的软笔触完全不搭，用户明确反馈"看起来很假"。
**替代方案：** 使用同心椭圆（通过 `draw_set_transform` 缩放圆形实现）叠加出土壤斑，宽高比约 4:1 符合院子伪等距透视；交互指示改为 `draw_polyline` 椭圆轮廓。
**当前状态：** 已在 PR #12 冲突解决 + 跟进提交中实施。任何未来触碰植物床绘制的 PR 须遵守此规则。

### 2026-10-01 · 相册按钮、动物目标、钓鱼收获——永久保可靠

**决策：** 以下三项反馈机制必须在每次发布后保持可用：
1. **相册按钮**：桌面 web 端鼠标单次点击必须可靠打开相册（无需多次点击）。
2. **动物目标弧**：玩家靠近可抚摸动物时，橙色弧线 + 地面环必须清晰可见（对比度充足）。
3. **钓鱼收获庆祝**：收杆成功必须有明确视觉反馈（屏幕闪光 + 扩散环 + 通知文字）。
**原因：** 这三项是核心交互回路；任何一项失效都直接破坏玩家体验闭环。
**执行方式：** 测试套件中已有 389 项检查，相关路径有场景测试覆盖；每次合并前必须 PASS。
**当前状态：** 已修复并作为 PR #12 的硬要求发布。

## 发布流程

### 2026-10-01 · 合并 + 真实 Godot 导出 + Pages 发布——无需询问

**决策：** 当 PR 通过测试（`[game-generic-tests] PASS`）且功能已验证，代理直接执行：
1. `git merge --no-ff <branch>` 到 main
2. `godot --headless --export-release "Web" dist/index.html`（使用当前安装的 Godot 4.7.2）
3. `bash tools/publish_gh_pages.sh` 发布到 gh-pages
4. 在 PR 描述 / 总结中报告新 `game-<sha>`、PCK 哈希、本次改动要点、残留风险。
**原因：** 每次询问增加不必要的往返延迟；流程已固化，代理可自主执行。
**当前状态：** 生效中。如需暂停（例如等待人工测试），用户可在对话中明确说明。

### 2026-10-01 · 不复制/重命名 PCK；不使用 handoff 分支的未审查代码

**决策：**
- 禁止手动复制或重命名 `.pck` 文件绕过 `publish_gh_pages.sh` 的验证逻辑。
- 禁止将 handoff 分支整体合并；如有需要，仅选择性 cherry-pick 已审查的补丁。
**原因：** PCK 哈希和 `executable`/`fileSizes` 一致性由脚本保证；绕过脚本会导致版本不一致。
**当前状态：** 生效中。

## 游戏设计原则

### 2026-10-01 · 无压力假期——核心不变

**决策：** 游戏永远不得加入以下元素：失败状态、倒计时、金币/体力、任务清单 UI（红点/进度条）、强制引导弹窗。
**原因：** 游戏名《悠长的假期》的核心承诺是"没有待办的几天"。
**当前状态：** 生效中。所有引导以软通知（底部淡出文字）形式呈现，无检查列表。

### 2026-10-01 · Playtest #3 (game-9069537) — 硬刷新回归失败分析与修复

**背景：** PR #12（game-9069537）在本地通过 389 项测试，但 playtest 硬刷新后三项核心反馈依然失败。

#### 根因分析

**1. 宠物目标弧（Pet target）完全不可见**

两层原因：

**(a) z_index 绘制顺序错误（主因）**：目标弧在 `YardWorld._draw()` 中绘制，而 `YardWorld` 是 Node2D，其 `_draw()` 渲染在 z_index=0 的世界层。动物精灵（FeltActor）作为 YardWorld 的子节点，同处 z_index=0 但在场景树中排列更晚，因此必然渲染在 `_draw()` 内容之上。牛/马精灵约 100-200px 高，轻松覆盖半径 42px 的弧线和箭头——玩家无论如何都看不见。

**(b) 透明度公式过于激进**：原公式 `proximity = (1 - dist/75)²`，在 85px 距离时 alpha < 0.05（低于绘制阈值），直接被跳过；60px 处也仅约 0.13。玩家在感应边缘（60-105px）走近动物时完全看不到指示。

**修复：** 创建 `WorldEffectsOverlay`（`scripts/game/world_effects_overlay.gd`），z_index=50，高于所有动物（z_index=0）。透明度改用线性衰减，60px 以内保持全亮，向外至 105px 平滑消退。

**2. 钓鱼庆祝扩散环不可见**

同样的 z_index 问题：庆祝环在 `YardWorld._draw()` 绘制（z_index=0），鸭/鹅精灵作为子节点在上层渲染，遮挡了从钓鱼点向外扩散的所有环。屏幕闪光 `_fish_flash` alpha 峰值仅 0.38，在水彩背景下几乎不可见。通知字号 16px、时长 3.2s，在玩家视线集中于行动按钮时极易错过。

**修复：** 庆祝环移入同一 `WorldEffectsOverlay`（z_index=50）；`_fish_flash` alpha 峰值提升至 0.62，加入 0.12s 保持段再消退；钓到通知字号升至 20px，时长延至 6s。

**3. 植物床"贴纸"感**

椭圆土壤已替换矩形（PR #12 正确实施），但深棕色（alpha=0.85）的椭圆在草地上始终可见，像一个固定的棕色贴片。

**修复：** 添加基于玩家距离的渐显逻辑：80px 以内全透明度，80-200px 平方衰减至 0。空地和种子状态随土壤一起淡隐；发芽/开花内容（绿色/粉色视觉）保持常显（自然融入背景）。

**4. 空闲引导提示不可见**

定时器逻辑正确（55s 首次，75s 轮换），但：（a）通知字号 16px / 时长 3.2s 在安静状态下太小太短；（b）昼夜相位切换通知（约 80s 一次）经常与空闲提示重叠，将其覆盖。

**修复：** 空闲提示只在无活跃通知时显示（否则延迟 6s 重试）；字号升至 18px，时长延至 8s；修复首条提示索引从 0 开始（原逻辑跳过 candidates[0]）。

**5. 相册按钮 Partial PASS**

Scale 弹跳从 1.04 提升至 1.08，点击可靠性不变。

#### 架构决策（本次固化）

- **WorldEffectsOverlay**：任何需要"渲染在所有动物之上"的世界层特效，均应置入此节点，不得在 `YardWorld._draw()` 中直接绘制。
- **变更（2026-10-02 playtest #4）：** 禁止写死 `z_index=50`。`FeltActor` / 玩家使用 `z_index = roundi(position.y)`（约 400–600），覆盖层必须每帧设为 `max(角色z) + N`。PR #13 / `game-8280e92` 的失败正是因为固定 50 画在动物脚下。
- **土壤渐显规则**：植物床土壤绘制必须基于玩家距离渐显，禁止在 >200px 时以高 alpha 强制显示棕色椭圆。
- **下一步（仍未开始）**：核心院子场景化——将院子从单张水彩图重构为真实 2D 场景（独立 Sprite 节点 + 碰撞多边形），这是所有视觉遮挡问题的根本修复路径。此步骤 playtest 明确说"还未准备好"，本次 PR 未触碰。

### 2026-10-02 · Playtest #4 (game-8280e92) — PR #13 真根因与结构性修复

**背景：** 硬刷新 playtest 再次 FAIL：宠物弧出现在牛/羊脚边而非上方、箭头缺失；钓到无闪光/扩环/庆祝文案；相册 chip 一次点击反馈不清。植物床近距渐显 PASS。

#### 真根因（相对 PR #13 文档的纠正）

1. **宠物/钓鱼覆盖层 z 写死为 50（主因）**
   PR #13 假设动物在 `z_index=0`，于是 `WorldEffectsOverlay.z_index=50` 即可压过精灵。实际上 `FeltActor.tick` / 玩家每帧执行 `z_index = roundi(position.y)`（院子里约 400–600）。覆盖层整层画在角色**脚下**。玩家看到的橙色只是脚底柔光从精灵边缘漏出 → 「弧在脚下/周围」；头顶弧与箭头被精灵盖住 → 「箭头缺失」。钓鱼扩环同理被鸭鹅盖住。

2. **几何锚点错误（次因）**
   弧与箭头以脚底 `position` 为圆心、仅上移 ~33px，对牛/马精灵高度远远不够，即使 z 正确也仍像「围着身体」而非「在头顶上方」。

3. **首次钓到通知被拍立得盖掉**
   `_reel_in_fish` 先发 `notice.fishing.caught*`，再 `_apply_rule(fish_first_catch)` → `notice.photo` 覆盖庆祝文案。屏幕闪光若遇 `reduced_motion` 会整段 return，连通知延长也不做。

4. **相册 pulse 过弱**
   scale 1.08 + 无 pivot_offset，桌面 Web 上一次点击的「开了」反馈不够。

#### 修复（本 PR）

- 覆盖层每帧 `z_index = max(所有角色/道具 z) + 8`，并 `move_child` 到场景树末尾。
- `FeltActor.marker_crown_lift()`：按 ground_anchor / 贴图高度算冠顶抬升；弧与箭头画在冠顶上方，脚底只留次要柔光。
- 钓鱼环时长 3.2s、更大更亮；首次拍立得后重发钓到通知；HUD 闪光峰值 0.78 且移到 UI 层最前；通知延长不受 reduced_motion 短路。
- 相册 chip：`pivot_offset=size/2`，pulse scale 1.16 / modulate 更高。

#### 残留风险

- 冠顶高度依赖 ground_anchor / 贴图近似，极端缩放或未配置 anchor 的物种可能略偏；若仍「贴身」需按物种微调 lift。
- 核心院子仍是单张水彩 + Canvas 叠加，未做场景化遮挡（out of scope）。
- Idle hint ~90s 未在 #4 观察到：55s 首启 + 繁忙通知仍可能推迟；未作为本次硬失败项重写。
