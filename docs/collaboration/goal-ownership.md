## 每张执行单必须直接可见

原 issue 顶部维护：**Owner、状态、当前子范围、明确非范围、active PR/精确 head、正在改的路径或方法、下一交付、依赖、接收回执**。使用 owner 标签和状态标签辅助筛选，但正文中的具体边界优先于整目录占用。`status:in-progress` 只用于有真实执行/分支证据的事项；指定未回执使用 `status:awaiting-receipt`，下一项用 `status:queued`，用户延期用 `status:deferred`。

开工先读原单最新状态、开放 PR 和 #242；发短认领/接收，写明方法/字段范围和首个交付，再开始修改。若他人仍在同一方法执行，只处理不冲突部分或显式交接；一个人负责整个 issue 不意味着永久占住整个 Main.gd。提交变化后更新 active PR 与精确 SHA；结束即释放已完成子范围，下一未开始范围不得冒称在写。不直接改他人分支，不把留言等同接收。
