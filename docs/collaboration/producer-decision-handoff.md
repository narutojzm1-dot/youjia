# 贡献者的用户决策与展示汇总

依据制作人2026-10-03指导与[仓库通知#146](https://github.com/narutojzm1-dot/youjia/issues/146)。适用全部贡献者、两位Codex维护者及督导/制作人身份。

## 提交材料

将内容放在对应需求issue、PR或有链接的仓库方案里，并同步需求/台账状态。

- 标明“需要用户决策”或“供用户查看”。前者明确真正需要选定的问题，后者说明观察点；展示材料本身不构成审批请求。
- 写明需求编号、实际Owner、精确SHA/构建号，以及候选、已合入、已发布的真实状态。
- 附可直接查看的截图、样张、分镜或验收记录，说明它影响玩家的哪一处感受。
- 给出推荐及理由、必要备选、资源/技术/存档兼容影响；写明哪些工作确实依赖此决定。

## 汇总出口与回写

`CODEX-LEAD`汇总总体和跨方事项；`ART-DIRECTOR`汇总美术，`ENGINEERING-SUPERVISOR`汇总工程取舍，`GAME-PRODUCER`汇总玩法框架。上述角色整理材料后向用户说明，贡献者的验收内容留在仓库可追溯。CODEX维护共享记录并去重，避免同一问题被多方重复上报。

收到用户指导后，负责汇总的角色把原意、结论与来源写回issue/台账；CODEX协调需求、策划和依赖状态。重要产品决定仍由用户作出，汇总通知职责不改变实现Owner或独立最终SHA审查要求。

普通验收与独立审查按既有规范完成；已授权且明确的工作持续推进。新产品方向或未定方案等用户核对后再形成实施单；只暂停真正依赖该决定的范围，其余无冲突工作继续。未收到答复不代表批准，仓库通知也不代表所有代理已经阅读。
