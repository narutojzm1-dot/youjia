# 独立 QA 报告与定时测试规范

来源：用户 2026-10-03 指定独立游戏测试，并明确报告须提交 GitHub、缺失规则需补齐。遵循 [统一上报规范](producer-decision-handoff.md) 与 [贡献规范](../../CONTRIBUTING.md)。本规范不修改玩法方向。

- GAME-QA 只做测试、复现、证据、报告和 BUG 台账，不开发游戏/修复，不代替既有 Owner 或产品决策。
- 每日 Asia/Shanghai 08:00、12:00、16:00 冒烟，20:00 深度体验。每轮先核对实际部署构建；main/Release 与线上不一致时分别记录，不将 main 当成线上。发现新版本做影响回归；定时轮询不代表部署时即时自动触发。
- 冒烟覆盖启动、入口、主要玩法最短闭环、存档恢复、高严重度回归；深测维护全玩法矩阵，覆盖长期进展、异常边界、输入/UI/音频、兼容与稳定性。实际游玩、自动测试和静态分析分别计数。
- 每轮（包括阻塞）在 `docs/playtests/YYYY-MM-DD-HHmm-game-qa/` 归档中文 README、BUG 清单、原始日志及相对链接证据；证据目录加 `.gdignore`。历史报告不覆盖。记录北京时间、环境、存档来源、实际 build、可核验 SHA、步骤/预期/实际、复现次数、严重度、状态、未覆盖项与关卡结论。无法核验的 SHA 明写未知。
- 按唯一编号去重；已知问题关联原 issue/记录，新问题先录 `docs/decisions.md`，可执行测试同步 `docs/requirements.md`。开发修复 Owner 由维护者分派，不自动认领。环境阻塞不算产品 BUG，未执行不算通过。
- 每轮以独立主题分支和 PR 提交报告；不得直接推 main。PR 按模板注明 GAME-QA、台账编号、候选/已发布版本、供用户查看/需要决策、证据及限制。合入仍须独立子代理审核最终 SHA，QA 本人不自审；报告提交不等于发布获准。
- 由 CODEX-LEAD、相关督导或 GAME-PRODUCER 按统一上报规范汇总给用户；重大产品选择仍归用户。完整覆盖不足时明确写“不足以判定全量发布通过”。
- 定时配置与报告提交分别验收：任务 ACTIVE 不等于已执行成功。执行端离线或浏览器连接失效时记录阻塞和实际运行时间，不伪造准点完成；GitHub 不可用时保存本地待提交产物，恢复后补提并标明延迟。
