- **覆盖关系：** 同一范围以最新用户明确要求为准；10月6日取消的是通用逐 PR 独审，10月8日 A/B 和10月11日 Grok 要求分别是明确例外。本文旧“报告合入须独立子代理审核”“QA报告PR仍按原约定待审”，以及旧入口、模板、定时心跳中的同类句子，不再给普通报告设置独审门禁；不能反过来借通用取消规则抹去修复例外。
- **23:00 的范围：** 北京时间（Asia/Shanghai）23:00 由 Leader 审查当日全部工作、精确提交/实际构建、QA 覆盖和未覆盖范围，并核对当天审查后的增量。它不是普通报告必须等到23:00才能归档的时刻；A/B 与 Grok 的合入前审核也不能延到日结补签。已有核对和证据可复用，资料归档不等于游戏发布放行。
- **真实阻塞：** “待审”必须说明适用门禁、责任人、完整 SHA 和具体下一动作。文档冲突、检查失败、具体未解决评论与证据缺口分别记录；不能只凭 PR 开放、旧正文或“缺独审”判定被流程卡住。普通报告可继续提交和补缺，不因修复子代理不可用停下独立测试。
- **边界：** 修复与纯报告分 PR；混入修复不能按报告规避 A/B。复杂、跨模块、存档/共享协议或影响不清的缺陷仍交现有 Owner。所有类型保留分支/PR，禁止直接推 main，不改检查或发布工作流，不以取消重复审核降低测试质量。未测仍为未测，历史证据不改写，已合入工作不因本次澄清重新审查。
