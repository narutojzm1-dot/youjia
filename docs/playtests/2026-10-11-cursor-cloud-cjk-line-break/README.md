# Web 中文折行不再把「。」单独甩到下一行（CURSOR-CLOUD UI 维护）

普通 Web 导出，浏览器模拟视口（非手机实机）。

## 修前

`before-280x653.png`、`before-390x844.png`：近郊观察「坡路草边」时，说明末句「篮子里的松果是在这里带上的」后面的「。」独占一行。

用同一段文字、同一个游戏字体在原生环境排版，任何宽度都会把「的。」一起换行（见 `test/cjk_line_break_suite.gd`）。只有 Web 出错。

原因：`project.godot` 没打开 `internationalization/locale/include_text_server_data`，它默认关闭。导出包因此不带文字服务器的断行规则和中文词典，中文退化成逐字断行，不守行首禁则。编辑器自带这份数据，所以原生测试看不出来。

影响范围：所有自动折行的中文，包括近郊说明、提示、通知、确认文字等，不只这一句。

## 修法

`project.godot` 打开 `internationalization/locale/include_text_server_data=true`。导出包会带上 ICU 断行数据，`index.pck` 里多了 `icudt78l/brkitr/...`。

**代价**：`index.pck` 从 69,626,676 字节涨到 74,424,284 字节，多 4,797,608 字节（约 +6.9%）。首次加载会多下载这部分，之后有缓存。

## 修后

`after-280x653.png`、`after-390x844.png`：同一场景下，「的。」一起换到下一行。

存档进度不同，所以背景天气和时刻不一样，与本改动无关。

## 回归

新增 `test/cjk_line_break_suite.gd`，已登记进 verify 与 TSV：

- 守住上面的项目开关，并确认文字服务器支持断行迭代器。
- 实玩复现句在 200–258 宽下，「。」从不独占一行。
- `zh-CN.json` 全部文案（6 字以上）用游戏字体 15/17 号，在 96–578 宽下逐宽排版，行首不出现「。，、！？；：）」』》〉】”’…」。
  - 「·」两侧带空格，用作分隔符，在它前面断行属正常，不计入。
- 去掉开关时，开关检查失败；修后 312 checks 全部通过。

原生环境本来就有断行数据，所以文案检查在原生里总能通过。它守的是今后新文案和字体在有数据时的排版；导出包里有没有数据，由开关检查来守。
