## 从玩家视角发生了什么

1. 点左岸原画中可见的**石头**：薄岸石世界点 `(515,560)`，以及玩家最容易点的大石头 `(510,612)`，同属不入池面的画石多边形。HUD 中文显示“目标：水塘岸石／拨一拨水”，英文显示 `Pond-side stones / Touch the water`；触屏、指针、空格、行动按钮共享这一精确目标。原本的池面点击继续钓鱼，鸭鹅仍能投鱼，草堆/花圃仍执行旧动作。持鱼或抛竿期间岸石不夺取当前行动。
2. 玩家从院内草地接近安全脚点 `(515,527)`；画面标记、移动终点和水面绘画锚点 `(568,580)` 各司其职。离得太远、尚在途中都**不提前泼出成功水纹**。抵达后才播放短时完整的手绘初始波与扩展波，并给出克制的“水面一圈圈散开”文字，绝不触发钓鱼上钩或获得物品。
3. 另一种彩蛋是**普通散步靠近池边**时独立出现的同一只青绿蜻蜓；无需点石、无需停住等随机倒计时，真看到足够时间才视作该会话已欣赏。它有两幅完整四翼绘画，低动效保持一幅稳定的收翼画。玩家可以继续走、暂停、切目标或去看相册；短时画面可取消，错过不失去任何内容，下次走近仍可再遇。它不是“点花箱也冒蝴蝶”的复制反馈。

画面由 Xvfb 下真实 Godot OpenGL 2D 渲染器取得。初版竖屏定帧夹具冻结了 `Main._process()`，导致镜头停在房屋、玩家虽到岸石但石头仍离屏；已更正为**实际竖屏相机跟随**后重拍最后两幅，不把该测试夹具错误误报为游戏功能。无音频设备时 Godot 输出 ALSA 警告，但画面、脚本和截图成功。

候选 Web 真点击发现初版多边形只覆盖水线上的一排小石，玩家最先点的**显眼大石头**会落空。依实际网页像素把多边形延伸到下方石身后，重导出候选包；浏览器按大石头中心点击确实看到“水塘岸石 · 拨一拨水”，主角走到岸边后才看到“指尖轻碰岸边，水面一圈圈散开”，相册保持 `0/11`，没有误钓鱼。这两幅短间隔浏览器截图并未拍到仅持续 1.65 秒的水彩动画，**画帧位置/透明度以六幅原生渲染画面为据**；不得把文案截图冒称 Web 逐帧验证。随后另点院内草地，玩家仍能正常移动。该观察仅是临时候选构建的实际浏览器结果，仍须等待正式 Pages 发布核验。
