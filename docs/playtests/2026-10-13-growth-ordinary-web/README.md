## 阻挡原因与修复前后对照

旧候选的实际 Web 现象是：第 4 天 15:40 至 16:08，角色在门口、时钟继续前进，按钮长期显示“正在做饭”；查看背篓后中鱼与圆石都仍为 1。玩家改点草地可以正常移动，晚饭点又开始等待取材，背篓附近有羊。单凭这些 Web 观察不读取或推断具体内存字段。

随后在隔离原生运行中复现因果链，记录见 [navigation-natural-before.log](native/navigation-natural-before.log)：普通羊的出生位置为 `(309,508.5)` / `(372,491)`，正常活动到 `(310.2198,512.9765)` 时覆盖背篓固定导航中心 `(335,522)`。原实现保留 `meal_basket` 意图和 walk goal，但路径为空；取材前尚无 `cooking_plan`，餐次过期检查被 pending-action 早退跳过，所以越过晚餐截止、跨日后仍保持“正在做饭”。中心附近 4 像素的可达点并未被覆盖，不能把整个背篓区域都视为不可到达。

修复保留物理交互中心和 18 / 20 像素到达阈值，只为餐食导航选择范围内实际可达终点。玩家仍须真正走近，不挪动物、不关闭碰撞、不远程取材。临时导航记录日期和餐次；餐次失效、目标丢失 / 被替换、10 秒无位移或 90 秒总时限时释放意图并冷却。食材仍由最终原子保存事务扣除，导航、取材表现不预扣库存。

同一组 [导航回归修复前日志](native/meal-navigation-before.log) 为 `28 checks / 10 failures`，修复后为 `28 / 0`。涵盖真实羊占位、途中重路由、保持碰撞、餐次截止、跨日、goal 丢失、保留玩家目的地、整个可接近区域被挡时取消，以及冷却后恢复。这些受控回归与上面的普通同档 Web 成功链相互补充。
