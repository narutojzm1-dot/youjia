# #40 静观天空自动放大：生产相机链路受控 Web 对照

基线 `c12a3d4750c974a4a34f42c78a2ded89bffefe6b`，Godot4.7.2、Chromium151，1280×720。CODEX-LEAD执行子代理按Leader明确指派，沿用用户去明显缩放的授权，不新增玩法。仅将 QUIET_SKY_ZOOM 1.14 改为1.0。

## 方法和限度

独立探针加载生产Main场景并进入院子，用Main._process每帧1/60推进真实世界tick、信号与相机插值。正常与低动效分别观察5秒（300ticks）与6.5秒（390ticks）；演员置固定点/pose以避免鹅马演出或行走干扰。截图中其他动物重叠是这个受控摆位的结果，不是自然玩法观察。天空触发时间5.5秒、hold4秒、cooldown28秒、中断及让位逻辑均未修改。

这不是公网自然复现，也不是其他镜头/摄影功能的全面验收。脚本记录实际Camera.zoom和camera_focus_requested，区分整幅相机变化与演员scale。JSON source_sha标基线，after的唯一运行时差异即本PR常量变化。正常模式两时刻演员呼吸会造成极小y比例差，低动效无此变化；14%来自相机请求，不能归因为马贴图。

## 修前

| 模式/时间 | 相机缩放 | 焦点目标因子 |
|---|---:|---:|

| 正常6.5秒 | 1.0145624 | 1.14 |

触发后实际收到zoom1.14，正常模式尚在插值，低动效几乎达到目标。截图可见房子、山、动物整体放大，而UI不放大。修前console/pageerror=0。

## 修后

两模式5秒和6.5秒均Camera.zoom=(0.8944445,0.8944445)，focus target=1.0；6.5秒仍收到天空focus请求并保持观察状态，所以只是取消自动放大。天空焦点和平移机制保留，不能说镜头完全不动。zoom=1.0也会进入Main原有 `_cam_target_zoom <= 1.05` 的玩家跟随分支（竖屏亦包括横向跟随），所以不声称平移轨迹与修前完全相同；本轮Web对照仅覆盖1280×720。修后console/pageerror=0。真实world.tick回归15/15，显式校验两模式zoom1.0及走动取消/冷却，不以被测常量自我对照。

## 复现

在基线独立worktree将两个txt复制为根目录sky_probe.gd/tscn，临时main_scene指向probe，导出Web并HTTP服务8820。browser.py参数before/after决定输出目录，按实际机器调整路径。生产Main仍负责首帧；驱动在报告存在后还派发一次first-frame以保障探针遮罩退出，不把此计为生产启动验收。PNG/JSON为实际Web输出，没有对画面作编辑。最终正常main_scene另行导出/冒烟与完整daily状态记录在PR验证评论；未合入/未发布时不称线上已修。
