# WORLD-BASKET 首片：钓获、存取与重开

Owner: CODEX-LEAD；需求 #503。基线 main `26c8d22bd7d71189752ba1cb224d1e5a6fa7bc89`，分支 `codex/lead-yard-basket`。本记录是候选实现证据，发布状态以 PR 和公开构建核验为准。

## 实现边界

院内 HUD 打开大背篓，读取原有探索 keepsakes（圆石、松果、落羽）；鱼通过版本化 `yard_inventory` 扩展保存数量和手持位置。钓获直接入篓，取一条/放回/既有定向投喂都等待 SaveStore 提交确认，不能靠界面先扣数。存储拒绝可重试；结果未知保留原操作并先确认，不能再发一笔取得重复物品。未知字段/版本不被修剪为“有效”库存。

保持旧探索账本和 Host/Gate 协议，未改 Web 存储模块。新库存关闭旧的生产手持鱼 20 秒消失规则；#231 钓鱼套件同步验证持久保留、miss 不改旧鱼、走向动物后只消费一次。历史到期验收不再是新玩法的要求。

打开背篓暂停小院，遮住收杆闪光，拦截背景输入。短横屏可滚动，触摸拖动不触发“拿一条”。中文/英文、390×844、844×390、320×568、568×320、1280×720原生布局通过。

尚未实现：草/鱼作为地面对象自主竞争取食、动物同行、beibei/鸡成长/乌龟关系故事。当前鱼仍经旧的定向投喂入口消费；这些后续功能不能因本 PR 被称为完成。

## Web 普通操作与限制

本地实际 Web release `http://127.0.0.1:8765/basket/index.html`，现有测试档未注入物品/存储：

1. 390×844普通点击进院→背篓，原有松果×1、鱼全零。
2. 1280×720点击池塘正常走到岸边并抛竿。前几次错过收杆窗口，背篓未加鱼。随后连续空格输入覆盖自然咬钩窗口（压力输入，不是一次精准收杆），只新增奇怪的鱼×1，手中为空。
3. 点击“拿一条”：库存变0、手持奇怪的鱼。刷新页面重新进入小院，390×844仍是手持同一条鱼，旧松果×1未变。
4. 点击“收回背篓”：手中空、奇怪的鱼×1。568×320滚动能看到该行和存回控件，关闭按钮保持可见。该标签页 warn/error 日志为空。

对应 `web-*.jpeg`；原生 `basket-*.png`。浏览器 viewport 模拟不等于物理手机触屏；实际浏览器存储故障注入、全平台/所有历史存档矩阵未在本片声称覆盖。公开部署尚须合入后核验，不重复发送已完成的10月6日日版邮件。
