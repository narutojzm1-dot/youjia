# 窄竖屏相册不再被翻页按钮撑出屏幕（CURSOR-CLOUD UI 维护）

普通 Web 导出，浏览器模拟视口（非手机实机），存档里有真实照片。修前截图来自 main 的同一份相册代码。

## 修前

- `before-280x653.png`：整张手帐比屏幕宽，「合上」被截在屏幕右边外，标题和书页也跟着偏右。
- `before-320x568.png`：还在屏幕内，但卡片比设计宽了 16px。

原因：书宽是 `屏宽 − 64`，但三枚翻页按钮按文字撑出的最小宽度合计为 96 + 96 + 64 + 两个 8px 间距 = 272px。320 宽时书宽只有 256，280 宽时只有 216，按钮排把整张卡撑宽。

## 修法

`scripts/main.gd` `_fit_album_frame` 按当前语言的字宽算出一排需要多宽（新增 `_album_buttons_need`）：

- 超过书宽：把「合上」移到第二行（新增 `_album_controls_low`），书页高度让出一行。
- 放得下：仍是一行，与 main 相同。

340 宽以上，包括 390、360、所有横屏，都保持一行不变。

键盘焦点停在「合上」时，转屏跨过分行宽度（约 336px），焦点会跟着按钮走，不会丢。这是独立审核第一轮发现的。

## 修后

`after-280x653.png`、`after-320x568.png`：手帐留在屏幕内，「往前翻 / 往后翻」一行，「合上」单独一行、整行宽。书页变矮后，照片改用相册已有的紧凑排法，照片配文字。

`after-390x844.png`、`after-1280x720.png`：与 main 相同。

## 回归

`test/album_layout_suite.gd` 加了 320×568、280×653，并新增检查：

- 手帐整体在屏幕内。
- 三枚按钮都在手帐里、字放得下、至少 40 高、互不重叠。

另有一项：焦点在「合上」时来回转屏，焦点不丢，并且只在一排放不下时分两行。

修前 280 宽有 128 处失败；去掉焦点恢复时，焦点检查失败。修后 85756 checks 通过。

## 实玩注意

本地反复导出后再用同一地址打开，浏览器会用 HTTP 缓存里的旧 `index.html`，加载器再按旧文件大小命中缓存里的旧 `index.pck`，结果跑的还是旧版本。本次修后截图是给地址加了 `?v=` 参数，绕开缓存后拍的。线上发布不受影响，因为每次发布的文件名带版本号。
