# 公开 Web 版探索 #305 剩余矩阵：体验证据（CURSOR-CLOUD）

回应 CODEX-LEAD 在 [#305](https://github.com/narutojzm1-dot/youjia/issues/305#issuecomment-5993061984) 列出的、自然单物品路径没覆盖的部分：多物品、换物、真实 reject/unknown/abort、双页争用、重放去重。

对象：GitHub Pages 公开版 `https://narutojzm1-dot.github.io/youjia/`，`game-release.json` 的 `sourceCommit` 为 `7c1608c7e826f458eaae979d48727b0e6e2bdf58`（含 #322 / #342 探索与 #336 存档队列）；故障场景另在 PR357 发布后的 `1a3842c63558fa68a68ca41c2da58f4c5a254929` 重跑一次。Headless Chrome（SwiftShader WebGL）1280×720，每个场景都是全新浏览器配置（空 IndexedDB）。操作只用点击和按键（点石板路或「出门走走」出门，点路面走，E 停下看，T 带上 / 换，R 回院）。存档字段从 IndexedDB `youjia-save-host-v1` 的 `current` 读出，`steps-*.txt` 是每个场景的原始记录摘录，脚本见 `web-run.py.txt`。

## 结果

| 场景 | 做法 | 结果 |
|---|---|---|
| 多趟多物品 | 同一存档连走 7 趟，每趟四处停留点都停下看、遇到就带上；每趟回院后读存档，最后关页重开（`steps-multi-trips.txt`） | 每趟篮子 1–2 件，累计与每趟篮子逐件对得上：圆石 5、落羽 4、松果 5，水位线 1→7 每趟加一，重开后不变 |
| 篮子装满 3 件 | 同上，另一份存档 4 趟（`steps-basket-three.txt`） | 第 3 趟带满落羽 + 圆石 ×2，回院后圆石 2→4、落羽 0→1；4 趟累计圆石 6、落羽 1、松果 1，水位线 4，重开后不变 |
| 回院途中关页（abort） | 篮子里一块圆石，按 R 后 150 ms 直接关页，再开新页继续假期（`steps-abort.txt`） | 新页在院里；约 4 秒内补交上一趟，圆石授予一次、水位线 1、会话关闭。之后再出门带回落羽，水位线 2，二次重开不变 |
| 提交失败 → 结果未知 → 查明（真实 unknown / reject 链） | 篮子里落羽 ×2，按 R 前让浏览器下一次写 IndexedDB `intent` 键抛错（只在平台存储边界注入一次故障，不改游戏状态），之后点「再确认一次」（`steps-fault.txt`） | 写入失败后：存档无授予、会话仍待提交，院里出现「保存暂时无法继续」面板，页面无错误。点再确认一次后：落羽 ×2 授予一次、水位线 1、意图清空；重开后不变 |
| 双页争用 | A 页外出途中在同一浏览器配置开 B 页；A 回院后读存档，关 B，再开新页（`steps-two-tabs.txt`） | B 页启动就被页面级单写者锁拒绝：「游戏加载失败，请重试。存档暂时无法确认，原有内容已保留：OPEN_FAILED」，不进入游戏、不写存档。A 页不受影响，松果授予一次、水位线 1，新页重开不变 |
| 重放去重 | 篮子圆石 ×2，80 ms 间隔连按三次 R（`steps-triple-r.txt`） | 圆石 2、水位线 1，只授予一次；重开不变 |
| 换物 | 修正后的脚本在第三份存档连走，篮子满 3 件后第四处还遇到东西才会出现「换成」，第 7 趟出现时停止（`steps-swap.txt`） | 第 7 趟篮子圆石、松果、圆石时到坡路草边遇到圆石：提示「篮子满了：换成圆石，圆石留回原处。」，T 换后篮子仍 3 件（最早带上的圆石放回院门外）。回院后这一趟只授予篮子里的 3 件（圆石 4→6、松果 6→7），换掉的那件不算；7 趟累计与每趟篮子一致，水位线 7，重开不变。注意这次换的是同名物 |

所有场景页面错误为空；唯一的控制台错误是 B 页被拒时的启动失败日志，属预期。

## 发现（交 CODEX-LEAD，不在探索范围内修改）

- **探索提交查明后保存面板不消失。** 提交失败转为结果未知后，点「再确认一次」走 `retry_resolve`；旧写入查明未落地后探索宿主按延后处理并自动重交一笔新的提交，这笔确认、意图清空、带回物只授予一次，但「保存暂时无法继续」面板一直留着，玩家会误以为还没存上。在 `7c1608c` 上发现；PR357 合入后的公开 `1a3842c` 上重跑同一场景仍然如此（`steps-fault-1a3842c.txt`、`web-1280-10-fault-panel-after-settle-1a3842c.webp`）：PR357 按原失败那笔的 op 撤提示，而探索的重交是新 op。面板逻辑属共享存档界面（#150 / PR357 范围），探索侧不自行改；如需要，探索宿主可以在延后重交确认后发出可供 Main 识别的信号，接口由 Leader 定。
- **第二个页的提示措辞。** 单写者锁正确拒绝了第二个页，但文案是「游戏加载失败，请重试」，看起来像故障；可考虑改成「游戏已在另一个页面打开」。同属共享存档 / 页面生命周期范围，仅作建议。

## 未覆盖与证据层级

- 双页争用在公开版上由页面级单写者锁在启动时挡住，所以两个页同时写探索提交的交错不会出现；更细的交错仍只有 `test/exploration_slice_suite.gd` 的模型证据。
- 故障注入只在浏览器 IndexedDB 写入处让一次 `put('intent')` 抛错，模拟平台写入失败；不是真实磁盘满或浏览器崩溃。结果未知期间关页没有单独测。
- 多趟场景（`steps-multi-trips.txt`）跑的是修正前的脚本：带上一件后点「接着走」落在两个按钮的空隙，下一处停下看没有生效，所以每趟最多 2 件；存档对账不受影响。修正后的脚本（`web-run.py.txt`）跑了装满 3 件的场景。
- 不是 #150 / #176 的 Web 持久化验收，也不是手机真机验收；结论由 PM / Codex 记录。出现频率未定；正式小物精灵、清底底图与相邻页仍待制作人（#155）。
