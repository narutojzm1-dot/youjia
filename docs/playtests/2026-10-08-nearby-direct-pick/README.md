## 实现与验证边界

普通地面物品读取本次既有行程/停留点随机结果的只读预览，不提前访问、保存、改变随机序列或暴露动物隐藏发现。点击沿正式道路走近并调用现有拾物事务；容量不足保留物品、不自动换出已有物品。未知保存等待旧事务，点地可取消等待，不锁住行走。人物/地图比例保持，所有视口用局部镜头和同一个点击变换。远端未开放提示保留正常回院和跨图入口。

实际Web验证发现两种同源输入顺序：合成鼠标先到时，回院会把后续触摸变成小院暂停；小院按钮先建近郊时，后续触摸会变成画卷移动。前者由真实触摸独占手势，后者让进入前已按住的手势先释放。只改近郊输入，不重写共享Main/Host。新增真实Viewport调度，修复前分别3/6项失败，修复后全部189项通过。

## 浏览器普通操作

本地官方Web导出，独立localhost候选。Chrome `154.0.8037.98`，DPR2，触屏390×844/844×390、鼠标1280×720，SwiftShader/headless。`browser-complete565.py`只输入真实鼠标/触摸；网络与IndexedDB只读。实际PCK及加载的10个存档模块逐字节对照本地导出，哈希见各视口`package.json`及`bundle.json`。

流程：标题→小院→正常出门；普通随机行程若院门没有物品，按真实回院/再出门进入下一趟，最多6趟，不固定种子；点击可见院门物品走近拾取→点地继续→回院收好→再次点HUD出门（人物留在起点）→回院→刷新标题→入院，核当前存档仅授予一次。完整原始输入（isTrusted）、候选画面与当前payload保留。触屏与桌面完整结果记录于`web/summary.json`。

旧交互进程在夜间暂停后过期，其未执行的回院/重开没有算通过。最初全记录读取还会把非当前记录误作状态，出现桌面观察超时；超时图证明已经进近郊。最终观察明确读取Host的`records/current`并复验，未为消除超时改玩家存档。原失败/部分记录放在`prior-web`及原始日志，不能代替最终流程。

844横屏曾在并行启动时超过180秒仍未显示首帧，该次没有执行玩法检查；同一包改为单独启动后完成10个状态、0脚本错误。保留启动超时日志，不以重跑通过宣称移动设备性能合格。最终390竖屏10、844横屏10、1280桌面12，共32个状态、0脚本错误。
