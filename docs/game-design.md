# 《悠长的假期》游戏策划基准

- 文档状态：当前产品基线；未决方向与建议会明确标注，不视为已批准功能。
- 最后更新：2026-10-02。
- 需求、决策、变更与游玩复核记录见 [产品决策与需求变更台账](decisions.md)。

## 一句话方向

在阿尔卑斯山脚的小院里度过一段没有待办的假期。玩家散步、观察动物，也能走近画面里的真实地点做轻巧互动；各处藏着无需追逐的有趣偶遇，把自然发生的表情和关系收进相册。

当前定位为**轻陪伴为主，轻放置为辅**：玩家在院子里休闲、观察和探索；动物与场景有自己的日常节奏，玩家离开后世界也可以温和地继续生活。玩家的互动会留下可感知的回响，偶尔改变动物之后的行为或一段小故事，让玩家感到自己确实来过、影响过这里。具体回响和离线变化按小步设计，不把游戏改成按时清任务、收菜或避免损失的经营游戏。

## 创作缘起与底蕴故事

这个游戏来自制作人一次真实旅行：他在同一个地方住了很多天，每天看着相似的天空、树木和水面，却一直觉得放松而不厌倦。早晨、正午、晚上各有不同的光；云每天变化，有火烧云，也有各种形状。即使面对同一片海滩，把一只汽水瓶放进前景，也能构成一张完全不同的照片。每天观察、寻找新角度、记录有趣的瞬间，让熟悉的景色不断有新发现。静静坐在那里，暂时离开工作生活，是这段体验最重要的感受。

游戏里的小院承载同一种愿望：不用不断换地图，熟悉的地方也能值得反复停留。天空、云、树木、水面、时辰和偶然发生的趣事一起变化；玩家既可以什么都不做，安静看一会儿，也可以主动选择前景和角度，把自己的发现拍下来。这里的探索是一种留心，不是完成清单。

## 从创作缘起形成的设计原则

- **先挖深一处熟悉的小院。** 通过时段光线、云形、天气、树水细节、动物日常与玩家行动的后续回响不断丰富它，再评估是否需要扩地图。
- **让天空成为持续观察的内容。** 早晨、正午、傍晚的光色和云层应有可辨变化；云的形状、密度、火烧云等可以逐步探索。不要只用全屏滤色代表天气变化。
- **让摄影表达玩家的眼光。** 自动拍照记录关系和偶遇；后续也要探索玩家如何选择角度、前景和画面关系。汽水瓶只是自由构图的例子，不预设特定道具或摄影 UI。
- **用轻量镜头呈现真实观察。** 主人安静坐在院子时，鹅和其他动物可能发生小冲突并从身边经过；可以尝试先用远景交代院子，再切到主人第一视角跟随，最后聚焦事件近景并留下照片。这是短小、可跳过的场内摄影演出方向，不预设为强制过场或复杂长 CG。
- **让趣味像生活一样发生。** 环境彩蛋有随机、有错过，也有再次发现；不把放松和探索改成打卡、集齐或绩效目标。

## 玩家承诺

- 玩家可以随时停下、离开或回来，不因缺席遭到惩罚。
- 主要乐趣来自动物的个性、日常动作、彼此关系和玩家偶尔介入后的回应。
- 玩家的行动可能在之后留下细小但可辨认的变化：动物记得一次照料、关系改变引出后续片段，或熟悉的地点出现新的故事。回响应由行为和世界自然呈现，不依赖关系数值条或待办清单。
- 世界有自己的随机性和可探索性。钓鱼空钩、动物临时改道或错过一场偶遇，都是生活的一部分；它们不能抹掉玩家已获得的长期进展，也不要求反复刷取来避免损失。
- 相册是观察与记忆，不是必须刷完的任务列表。
- 院子首先要让人愿意停留；任何进度系统都不能压过安静、温暖和松弛感。

## 设计边界

以下原则来自现有产品决策，除非用户明确更新方向，否则继续生效：

- 不加入失败状态、惩罚性倒计时、体力或强制登录。
- 不加入带红点、进度条或催办感的任务清单，也不弹强制引导。
- 资源或奖励若加入，只能服务于轻量布置与表达；不得形成必须反复劳动的经济压力。
- 钓鱼允许空钩和随机结果，这是世界的一部分，不是玩家绩效失败。错过咬钩可以失去这一次机会，但不应造成永久损失、进度倒退或必须盯屏等待；玩家可以轻松地再次尝试或转去做别的事。
- 动物目标提示、行动按钮、键盘和触屏要讲同一件事；玩家应能看懂目标、行为和反馈的关系。
- 美术动作先保证轮廓、朝向、地面接触和角色意图清楚，再增加装饰性粒子。
- 用户确认本作的美术定位是「每一帧都是精致的绘画效果」，现有表现应继续保持：动物的**新姿态必须是同角色、同画风的完整画作**，与原角色尺寸、透视、锚点和朝向连贯；不能把已张开的翅膀简单压扁或扭曲当作收翅/卧姿。
- 主动交互成功后由**实际接受互动的对象**给出短而清楚的回应；不能因未命中或物品已过期而显示爱心。为减少干扰，先让鸭/鹅吃鱼在自身附近轻轻冒爱心，低动效保持可读而不漂浮；其余动作按 [REQ-20261002-008](decisions/REQ-20261002-008.md) 逐项审计，不以通知文字代替所有动物回应。
- 用户明确把**场景可交互性、交互丰富度和有趣彩蛋**定为下一阶段核心。房屋花箱、池塘岸边、围栏边等新环境热点要有可达目标、独特对象回应和合画风的偶遇；彩蛋是可错过的生活，不是要集齐的任务或天气/日期签到。各切片与现有动物、植物、钓鱼目标的输入优先级须一致。见 [REQ-20261002-009](decisions/REQ-20261002-009.md)。
- 栅栏边的观察只是在**院内草地**停步、看见栏脚的植物和棚檐的轻动静；画中的木门仍是静态背景，不显示开门、不让角色穿栏进棚。草叶摇动使用两幅完整手绘姿态，不拉伸原背景或让低动效玩家失去回应。
- 玩家遇见可记住的一刻时，是**旅人随手拍下真实事件**，不是镜头无来由突然推近。首次成功保存的新照片要短暂展示同一张有纸质画框的成片、写明实际假期天数和匹配事件的短句，再轻轻收入相册；移动或打开界面可直接打断展示但不丢照片，低动效使用静帧。已有照片、补抓旧存档和未记录日期的旧快照不能假装新拍或凭空写“第一天”。见 [REQ-20261002-010 摄影体验方案](architecture/photo-diary-arrival.md)。
- 用户试玩正式摄影版认可拍立得显影，又明确要求更多真实动物抓拍、可变化但不虚构的日记题词与可翻的手账。REQ-013 只在**确实出现且入镜**的鹅卧姿、两羊靠近、池边鸭鹅等事件留一张照片；题词从符合现场的有限短句中抽取一次并存进快照，不能每次翻页重新随机改写历史。旧照片无变体沿用原句，日期缺失绝不补写“第一天”。宽屏双页、手机单页只浏览已拍记忆，不显示锁定槽、收集完成率或催促。见 [REQ-013 方案](architecture/scrapbook-encounters.md)，正式发布前不计入线上功能。REQ-012 的玩家自由构图与天空变化是独立方向。

## 体验循环

### 一次短暂游玩

1. 进入院子，立即看见动物当前在做什么。
2. 走近一个动物或环境点，界面说清目标与可以做的动作。
3. 玩家进行一次简单互动；角色和动物都以动作、声音或表情作出回应，某些互动还会改变动物之后的选择或埋下一段后续故事。
4. 有时会在门前、岸边或草地偶遇一件小事；结果允许有随机性，有意义的瞬间可以被相册记下，玩家也可以什么都不做，直接继续观察或离开。

循环的每一步都应可选，不出现“今天还有事情没做完”的压力。

### 长期陪伴（已确认方向，具体系统逐步设计）

- 院子按温和的日常节奏发生变化，离开期间不出现资源损失或动物受苦。
- 动物有容易辨认的作息、偏好、情绪与同伴关系；玩家互动除即时反馈外，可以改变接下来一段行为，并在之后的偶遇、表达或照片题词中形成回响。
- **关系是行为系统的候选底层。** 动物之间可以有不同的亲近、回避或冲突倾向，并受各自的个性、当下状态和共同经历影响，进而产生不同的相处行为。比如大鹅可以和马争执，却和草泥马和平相处；玩家的照料也可能改变之后的关系和故事。先用少量可观察、可解释的行为验证轻量关系模型，不把关系做成显眼的数值条或每日任务。
- 探索、随机性和惊喜来自这个世界本身。新增互动和彩蛋应让熟悉的小院展现不同侧面，不将偶遇变成要集齐的任务或每日指标。
- 长期回报优先是动物行为与关系故事、相册记忆、庭院表达和季节记忆，不以数值膨胀为主。
- 离线模拟、回归摘要、装饰解锁及其速度仍需评估保存兼容和技术成本；实现前先定义玩家能感知到的变化和缺席保护。

## 建设顺序

### P0：让基础体验读得懂、动得自然

- 在 PR #27 候选中把默认速度从约 39 提到约 61.4 px/s；步态相位按实际位移推进，新的帧频和足部滑动待 Web 实玩校准。
- 为抚摸、招呼、拿草、喂食、钓鱼增加短而清楚的角色动作。
- 目标提示显示动物名称和具体动作；目标指示器稳定位于目标脚边；按键、HUD 和点选目标保持一致。
- 行为完成时，立即给出角色动作、动物反应与简洁声音反馈。
- 鸭/鹅投鱼成功的首个回应与 REQ-001 主角动作分属不同切片；其余现有主动交互反馈应分阶段补足，不为追求爽感加入任务压力或无端刷屏。
- 按 [REQ-20261002-009](decisions/REQ-20261002-009.md) 为真实画面里的花箱、岸石等增加地点本身的可选互动和不同种类的低频彩蛋；先保证目标能被准确理解、旧钓鱼与花圃操作不被抢占，再逐处增加绘画层次，而不是增设日常清单或一批同款爱心。

### P1：让动物像不同的个体

- 先实现共享状态：闲逛、观察玩家、休息、进食、被触碰后的回应。
- 大鹅不要长期保持张翅威吓姿势；保留已批准的张翅原画用于有性格的活动状态，并以同质量原画补足**收翅安静站立**和**伏卧休息**，按自然作息错开切换。详见 [REQ-20261002-004 增补决策](decisions/REQ-20261002-004.md)。
- 为各物种做少量高辨识度循环：鹅摆头/啄食/短暂扇翅，鸭理羽，马甩尾，牛咀嚼，羊抖毛，羊驼吐舌或吐痰。
- 以互动触发状态变化；动作需节制、错开时间，避免全体同时表演。

### P1：落实轻陪伴方向并补全留园理由

- 先完成“注意到动物—互动—动物回应—记住这个瞬间”的循环。
- 设计少量从真实互动出发的后续回响，优先验证“动物之后的行为/小故事是否让玩家感到被记得”；避免先做通用任务、关系值或对话引擎。
- 以时段天空和自然光变化、自由取景为方向，先产出一处小院的表现方案和摄影构图原型；验证熟悉场景能否因云、光与前景组合持续给玩家新发现。
- 再逐步引入离线生活、缓慢园景变化和温和的回归摘要，并验证旧存档兼容和缺席保护。
- 不先堆新地图、货币或任务清单；若加入装饰成长，要让玩家能随手使用、没有失败成本。

### P2：让天气与季节真正改变院子

- 先接通已有晴/阴资源并检查美术连续性，再考虑新增下雨、初雪或四季资源。
- 天气需要可见的环境反馈；季节需要改变植被、光线、动物行为或可收集记忆，而不只是全屏染色。
- 缩短从新档到首次明显季节变化的时间；季节长度须配合是否有离线推进的产品决定。

## 待决策问题

1. 哪些玩家互动最适合产生后续回响？先选少量动物关系和小故事做验证。
2. 哪些变化应跨离开和重新进入游戏保存，哪些只在本次假期或短期内发生？
3. 玩家回来时，哪些变化值得展示？必须保证缺席不导致惩罚。
4. 相册之外的长期回报，以庭院布置、动物个性档案还是新区域为主？
5. 首个天空/摄影原型选择哪些时段、云形和前景构图？新增雨雪或四季资源如何控制制作和 Web 性能成本？
6. 是否扩充大鹅专属互动（梳理、喂食、跟随），并让钓到的鱼成为可选礼物？

## 变更规则

- 新功能必须说明它服务的玩家承诺、进入哪个循环、带来的动作/美术需求和无压力边界。
- 方向未决的条目只能作为候选方案写入台账，不得在实现中悄悄变成已批准规则。
- 每次涉及体验、玩法、美术资源或进度节奏的 PR，更新本文件与台账；纯工具性改动可只更新台账。
- 当前产品状态截至 2026-10-02 正式 Web `game-e2d12b7`；旧体验记录应标清对应构建，不能覆盖现状。
- 以最新线上构建为目标复核；功能合并或发布后，登记构建号、证据和遗留问题。
