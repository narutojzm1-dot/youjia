# 《悠长的假期》游戏策划基准

- 文档状态：当前产品基线；未决方向与建议会明确标注，不视为已批准功能。
- 最后更新：2026-10-02。
- 需求、决策、变更与游玩复核记录见 [产品决策与需求变更台账](decisions.md)。

## 一句话方向

在阿尔卑斯山脚的小院里度过一段没有待办的假期。玩家散步、观察动物、偶尔照料或互动，把自然发生的表情和关系收进相册。

当前定位沿用 README 和既有决策中的“休养观察游戏”。建议的延伸方向是**轻陪伴、轻放置**：让院子在玩家离开时也能温和地生活，但不把它改造成需要按时清任务、收菜或避免损失的经营游戏。放置强度、离线成长速度和长期奖励仍是待产品决策事项，不能仅凭本建议加入。

## 玩家承诺

- 玩家可以随时停下、离开或回来，不因缺席遭到惩罚。
- 主要乐趣来自动物的个性、日常动作、彼此关系和玩家偶尔介入后的回应。
- 相册是观察与记忆，不是必须刷完的任务列表。
- 院子首先要让人愿意停留；任何进度系统都不能压过安静、温暖和松弛感。

## 设计边界

以下原则来自现有产品决策，除非用户明确更新方向，否则继续生效：

- 不加入失败状态、惩罚性倒计时、体力或强制登录。
- 不加入带红点、进度条或催办感的任务清单，也不弹强制引导。
- 资源或奖励若加入，只能服务于轻量布置与表达；不得形成必须反复劳动的经济压力。
- 钓鱼等活动不能让玩家因没盯住短时间窗口而受罚。当前实现存在 6 秒咬钩窗口，与此原则冲突，列入复核项。
- 动物目标提示、行动按钮、键盘和触屏要讲同一件事；玩家应能看懂目标、行为和反馈的关系。
- 美术动作先保证轮廓、朝向、地面接触和角色意图清楚，再增加装饰性粒子。

## 体验循环

### 一次短暂游玩

1. 进入院子，立即看见动物当前在做什么。
2. 走近一个动物或环境点，界面说清目标与可以做的动作。
3. 玩家进行一次简单互动；角色和动物都以动作、声音或表情作出回应。
4. 有意义的瞬间可以被相册记下；玩家也可以什么都不做，直接继续观察或离开。

循环的每一步都应可选，不出现“今天还有事情没做完”的压力。

### 长期陪伴（候选方向，尚待产品决策）

- 院子按温和的日常节奏发生变化，离开期间不出现资源损失或动物受苦。
- 动物有容易辨认的作息、偏好、情绪与同伴关系；互动可以影响它们接下来一小段行为。
- 长期回报优先是新动物行为、个性记录、庭院布置和季节记忆，不以数值膨胀为主。
- 离线模拟、回归摘要、装饰解锁及其速度需先评估保存兼容与技术成本，并经产品决策后再实施。

## 当前游戏内容与已知缺口

| 系统 | 当前情况 | 对体验的影响 |
| --- | --- | --- |
| 院子与美术 | 单张水彩院子背景，角色与动物叠加绘制 | 氛围突出；天气、季节和物体遮挡受静态背景限制 |
| 玩家 | 默认 16 帧走路序列；位移速度缩至约 39 世界像素/秒；主要只有走路与静止 | 横穿院子慢，互动时缺少身体动作 |
| 互动 | 捡草、喂/牵羊驼、抚摸部分动物、钓鱼、种花 | 行为有了，但动作、目标和结果的可见联系不足 |
| 动物 | 会闲逛、休息、转向；多为单张身体图配脚部步态，部分动作依赖表情贴图替换 | 鹅缺少明显摆头、眨眼、扇翅等循环；多数互动不改变身体动作 |
| 相册 | 11 个可记录瞬间 | 是当前最清晰的收集目标，但玩家不容易预见如何发现其余瞬间 |
| 时间与花圃 | 游戏内一天为 600 秒游玩；花朵需跨多个游戏日成熟 | 等待偏长；代码仅随运行中的模拟时间推进，未实现离线推进 |
| 天气 | 有自动与手动状态切换；实际背景绘制始终使用晴天资源 | 按钮状态变了，场景观感变化很弱 |
| 季节 | 按假期天数叠加低透明度色层；第 13 天后进入秋色 | 最早需约 120 分钟连续在线，场景变化难以辨认 |

详细证据和游玩截图见 [2026-10-02 在线版游玩复核](playtests/2026-10-02-game-1347743.md)。

## 建设顺序

### P0：让基础体验读得懂、动得自然

- 把行走速度和动画步频解耦；校准加速、减速、转身和停步。
- 为抚摸、招呼、拿草、喂食、钓鱼增加短而清楚的角色动作。
- 目标提示显示动物名称和具体动作；目标指示器稳定位于目标脚边；按键、HUD 和点选目标保持一致。
- 行为完成时，立即给出角色动作、动物反应与简洁声音反馈。

### P1：让动物像不同的个体

- 先实现共享状态：闲逛、观察玩家、休息、进食、被触碰后的回应。
- 为各物种做少量高辨识度循环：鹅摆头/啄食/短暂扇翅，鸭理羽，马甩尾，牛咀嚼，羊抖毛，羊驼吐舌或吐痰。
- 以互动触发状态变化；动作需节制、错开时间，避免全体同时表演。

### P1：确定并补全留园理由

- 先完成“注意到动物—互动—动物回应—记住这个瞬间”的循环。
- 之后评估是否引入离线生活、缓慢园景变化和温和的回归摘要。
- 不先堆新地图、货币或任务清单；若加入装饰成长，要让玩家能随手使用、没有失败成本。

### P2：让天气与季节真正改变院子

- 先接通已有晴/阴资源并检查美术连续性，再考虑新增下雨、初雪或四季资源。
- 天气需要可见的环境反馈；季节需要改变植被、光线、动物行为或可收集记忆，而不只是全屏染色。
- 缩短从新档到首次明显季节变化的时间；季节长度须配合是否有离线推进的产品决定。

## 待决策问题

1. 长期定位保持“休养观察”为主，还是正式增加离线成长，成为更明确的轻放置游戏？
2. 玩家回来时，哪些变化值得展示？必须保证缺席不导致惩罚。
3. 相册之外的长期回报，以庭院布置、动物个性档案还是新区域为主？
4. 是否扩充大鹅专属互动（梳理、喂食、跟随），并让钓到的鱼成为可选礼物？
5. 是否新增雨雪或四季美术？应在确认视觉方案与运行成本后再生产成套资源。

## 变更规则

- 新功能必须说明它服务的玩家承诺、进入哪个循环、带来的动作/美术需求和无压力边界。
- 方向未决的条目只能作为候选方案写入台账，不得在实现中悄悄变成已批准规则。
- 每次涉及体验、玩法、美术资源或进度节奏的 PR，更新本文件与台账；纯工具性改动可只更新台账。
- 以最新线上构建为目标复核；功能合并或发布后，登记构建号、证据和遗留问题。
