# #48 自由取景首片：供制作人选择的两种范围

**状态：建议，未获产品批准；没有实现或开启开发认领。** CODEX-LEAD整理，依据 main `9cc7a09`。本材料只决定第一片做到哪里，不改变已确认的轻陪伴定位，也不重新立项已完成云带/草叶/安静观察或已去除的强缩放；静坐电影演出D继续延期。

## 需要你选的一件事

**第一步更希望“能把自己选的院景照片存到设备”，还是“照片直接留在游戏手账里，重开游戏还在”？**

- **A：院内取景，保存到设备（建议先做）**。先体验自己选画面；不改现有事件手账与存档结构。
- **B：院内取景，加入游戏手账**。重开仍可翻看自己的照片；同时做新的照片身份、存档兼容和手账入口。
- **C：暂缓自由取景**。先继续现有自动留影与院外探索，不新增摄影入口。

A、B都只取院内现有景物：可移动画框选择画面关系，固定倍率，不拉近/拉远游戏镜头、不添加汽水瓶等前景道具。B不是“批准A以后默认也做”；选择A不会悄悄开启手动相册功能。下述按钮称呼只是操作说明，非已审UI设计。

## 已确认与当前真实能力

用户已确认同一风景反复观察、自然摄影与玩家构图方向；尚未批准具体摄影UI、前景道具、任意照片容量或自动删除规则。[原拆分](../architecture/yard-revisit-split.md) 是2026-10-02研究边界，其中当时云带未交等状态不能覆盖现状；最新REQ012明确A/B/C观察已交，PR308已移除旧1.14推近。[策划](../game-design.md) 的摄影段要求真实事件、真实天数、克制显影，不虚构题词。

当前照片**不是截图图库，也不是通用手动快照**：

- `scripts/ui/photo_moment.gd:34 capture` 要求事件rule_id及院子 `_backdrop` Sprite2D，采集Sprite/AnimatedSprite、Line2D、YardPropVisual与影子，保存focus/span后重绘。默认按事件裁画面，很多事件还主动移除旅人和线条；不能将这份事件函数原样当“玩家看见什么就拍什么”。任意Control、自绘探索物件、HUD或其它特效不是自动通用支持。
- 同文件 `sanitize`：version1、单张items≤64、points≤64，受限纹理路径/天气/坐标；这些是技术验证界限，不是用户相册数量承诺。
- `scripts/persistence/save_data_codec.gd:clean_moments` 只保留album中且属于 `ExpressionCatalog.all_ids()` 的ID；`YardWorld._apply_rule` 按事件首张/缺快照补录。目前同一事件不是反复追加任意照片。随便塞入manual-ID会被清理，不能说“共享存档已经有，所以手动照片接按钮即可”。
- `SaveStore.set_album/request_album` 与Main确认后成片链已有；既有照片只有真实确认才展示为保存。Host仍可复用，但新语义须明确接入，unknown不能冒成功。
- `web/save/budgets.mjs` 固定生产预算：单源/普通写各1,572,864字节，导入3,670,016字节，全记录33,554,432字节。它们不是可存多少张的固定数量，旧原文保全等也占用空间。现有15张密集样本验证不能外推成无限手动相册。
- 近郊首片已经能正常走、看、拾物、回院；这不表示其自绘画卷/物件已具备PhotoMoment适配。A/B首片均不改Cloud探索，不把近郊摄影当现成功能。

## 两种可落地首片

| 选择差异 | A 保存到设备 | B 留在游戏手账 |
|---|---|---|
| 玩家操作 | 在院子主动进入取景，画面中平移固定大小画框，按一下快门；成片预览后主动保存图片或返回 | 同样取景/快门，进入待保存状态；真实存档确认后成片可从手账的新“随手拍”入口查看 |
| 画面边界 | 画框不得越出已有画作；不改变相机倍率。拟在按快门瞬间截取院景专用渲染帧，排除HUD/提示/操作框 | 首片同一固定比例/倍率，保存真实采集时刻的场景记录和选定裁框；不得拿旧事件快照伪装新拍 |
| 留存位置 | 浏览器/设备图片文件；不进游戏相册、不增加collected、不触发原事件成就式首张逻辑 | 游戏自己的手动照片记录，与自动事件ID分开；旧自动照片及其首次记录保持原样 |
| 重开 | 游戏不保存手动照片列表；用户成功存下的图片由设备保管。取消下载不提示已存入设备 | 已确认的照片重开可见，未确认/失败保留真实状态；原图日期/画面/题词不能重算改写历史 |
| schema与公共框架 | 不改SaveDataCodec/Host磁盘schema。需要新增院景只读捕获和浏览器用户主动下载路径，不是假定现有捕获函数已支持 | **需要扩展手动照片身份/记录模型与旧档兼容**，不能仅改UI。可复用现有串行提交、持久回执/恢复，不另造Host；是否保存场景快照而非像素文件须按下列技术门禁确认 |
| 数量与失败 | 不私设照片槽位/自动删图；每次只处理本次成片，取消返回即可 | 不承诺无限、不私定数量配额或自动删除。沿既有字节保护写前拒绝，明确“这张还没保存”，保留旧图/原库并允许取消或设备导出。若用户期望管理/扩容，应另提具体方案，不能偷加删除策略 |
| 资源 | 现有院景，克制纸片成片；不新增摄影道具/角色动作/天气画 | 同A；真实快照重绘需检查当前所有拟入镜物件/时段特效能否忠实保存，不够时明确返修适配 |
| 最大风险 | 浏览器下载/分享能力及触屏手势冲突；“下载已发起”不等于用户已在设备找到文件 | 新旧照片身份、顺序/题词、预算增长、unknown/重试、旧资源未来替换兼容；实现面明显更广，但无需等待腾讯云 |

**为什么推荐A：** 用户能直接判断平移画框是否表达自己的眼光，同时不将手账新记录模型、容量体验和迁移混到第一片。A也有真实实现门禁，不是一个现成功能开关；若最重要的是游戏里的长期记忆，应直接选B，避免先交一个不满足留存期望的下载功能。

## 实施前已能明确的技术门禁（不是工期猜测）

既有REQ010明确不以HUD截图伪造事件照片。A提议的是**另行批准的设备图片导出**，不替换该事件快照契约，也不把导出图片写回事件相册；若制作人不接受这种分离，应选B或C。

A：用院景独立渲染目标在快门同一帧取像素，验证人物/动物/云/植物等可见项与预览一致，排除HUD；取景时暂停场景还是继续观察尚属操作细节，建议继续观察、仅快门冻结本张，取消立即回正常散步。浏览器由真实用户手势发起导出，覆盖桌面和触屏失败/取消，不自动弹一串下载；无窗口缩放或拍照冲刺动画。设备导出路径目前无现成交付证据，须先完成可行性验证，失败不能悄悄改成B。

B：先证明现有PhotoMoment采集/重绘对一张主动院景照片的实际对象覆盖；本片不沿用事件自动删旅人的逻辑，也不编造事件题词。手动记录唯一身份/日期/裁框与静态题词一次冻结，旧事件ID名单继续兼容。若现有快照无法忠实还原当前画面，必须明确新增受支持对象/渲染信息，完成版本兼容审核后再写盘，不能退化成“相册显示差不多”。只在真正durable回执后声称保存；确认丢失、重试、双页占用、预算拒绝、关页恢复必须零重复/不丢旧照。题词建议只真实日期和“随手拍”，不猜图中故事，不新增编辑器。

两方案共通验收：固定倍率/越界限制明确，鼠标与触屏可取景、可取消；连续按快门不会多次消费输入或无限排队；无拍照任务/红点/收集率/奖励/错过惩罚；低动效没有移动成片动画。需独立最终SHA审查、适用回归/Web导出和普通真实操作证据，不能把方案图片当已做UI。
